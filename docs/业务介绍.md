# 小慧 · 业务介绍

「小慧」是一套 HR 数字员工：把招聘、入职、培训、绩效、行政拆成五条专线，再加一个只负责分发的总控。人面对的是「小慧」，系统按业务把活派给对应专线。

它不是一个什么都会答的聊天机器人，也不是人力资源系统本身。花名册和部门进度在独立的 HCM 里；小慧只读、催办、准备材料。人事决定仍由人做。

当前数据是教学与演示用，不能当作真实人事档案。

---

## 谁在用、从哪进

| 对象 | 入口 | 典型事情 |
|------|------|----------|
| 员工 | 飞书私聊或群里 @ | 问年假、报销、社保等制度 |
| HR | 飞书 / WebChat / CLI | 筛简历、看入职进度（含第 7 天）、按点名出培训稿、出 360（不定级）、查出月报、查别人的合同薪资 |
| 主管 | WebChat | 筛简历、看入职进度、出培训稿、出 360 看板 |
| 系统自己 | 定时任务 | 入职 7/30/60/90 天跟进；月末出 HR 月报 |

飞书问政策直达行政，不经过总控。WebChat 先到总控，总控判断属于哪条专线再转过去，自己不答政策、不打分。飞书 HR、WebChat、CLI 可以查花名册上别人的合同薪资，也可以补跑月报（数字仍由脚本算）。飞书非 HR 不能看他人工资、不能出月报。月末仍有宿主机自动出报。

对员工来说门口就是小慧，不必知道后面有几条专线。

## 五条业务线

### 招聘

把投递变成可核对的材料，供 HR 初筛。

- 从企业邮箱收未读简历，转成结构化档案
- 抽取结果要能回溯到原文；评分前去掉年龄、性别、婚育、户籍等敏感项
- 按岗位做 8 维评分和排序，给出建议动作（例如建议进入面试）
- 生成候选人画像；在已建人才库里按相似度找人，并解释为什么像
- 面试录音可转写、分发言人，再整理成纪要，口述数字对照简历回核

不决定录用或淘汰。不爬招聘网站。人才库里没有的人不会现编名单。

### 入职

跟踪新员工有没有准备齐，不代替各部门办事。

- 对照 HCM 里合同、账号、设备、培训、Buddy 五个节点的真实进度
- 合同内容、账号权限两道门必须人批准或拒绝，小慧不能代批
- 五部门都完成后，才挂试用期 7/30/60/90 天跟进
- 可查单人进度，也可出全部新人看板

不在 HCM 里建人、不填部门产出。部门没做完就催办，不把「未开始」写成「已完成」。审批卡住超过三天只催办，不自动放行。

### 培训

按点名的主题生成培训物料草稿，供讲师修改后使用。

可按 ADDIE 出：需求分析、课程设计、PPT 大纲、讲师手册、学员手册、课后测题、交付指南、评估表。用户只点了其中几份，就只出那几份。

不组织场地和签到。素材目录里没有的制度、数字、名称不写进去。每份稿标明「AI 辅助生成，讲师审核后交付」。

### 绩效

把 360 反馈收成面谈和校准会能用的材料。

- 摄入反馈表，校验齐全后再用脚本算各视角、各维度分数
- 整理共识、分歧和面谈建议
- 出雷达看板

不给出 S / A / B / C。缺自评不出总表。评价人在报告里只用角色称呼，不用真名。定级仍走主管初评、隔级复核、校准会。

### 行政

员工问制度时，先检索公司政策知识库，再按原文答复，并标明出处。

答年假天数、报销标准这类制度问题。员工问自己的工资、考勤、个税，转给人事。飞书 HR、WebChat、CLI 可以按花名册查看别人的合同薪资，数字必须来自花名册脚本。碰到个案争议、劳动仲裁、知识库没有依据、或需要破例审批，转给人事。检索不到不用通用常识硬答。

月报读业务表、算指标、出图，发布成看板。数字全部由脚本计算。月末自动出一份；HR / WebChat / CLI 也可以当场补跑。

## 总控做什么

总控只做三件事：判断这条需求属于哪条专线、转过去、把结果转述回来。

年假几天、这份简历多少分、入职能不能批，总控都不自己答。专线之间也不互相派活。一次请求只进一条专线；看不准就问人，不猜。

---

## 人必须留下的决定

| 事项 | 小慧给什么 | 人定什么 |
|------|------------|----------|
| 简历筛选 | 脱敏后的分数、排序、疑点 | 谁进面试、谁录用 |
| 入职 | 进度、待审正文、催办 | 合同和账号批不批 |
| 培训 | 物料草稿 | 能不能发给学员 |
| 绩效 | 聚合分数和面谈材料 | 最终等级 |
| 政策红线 | 能引用的制度原文，或说明转人工 | 个人账、争议、破例 |

设计原则：对个人有重大影响的决定不交给算法。关键数字走脚本和校验，过不了就停，不用流畅的中文代替做完。

---

## 明确不覆盖

- 不替代 HCM：花名册和部门节点由人在 HCM 填写
- 不自动执行淘汰、定级、批准入职
- 不回答未写入公司知识库的「好像应该是这样」
- 不把演示花名册或演示绩效等级当作真实人事结果
- 不组织线下培训现场

## 和现有系统的关系

```
员工（飞书） ──政策问答──► 行政 ──检索──► 公司政策知识库

HR（WebChat / CLI） ──► 总控 ──► 招聘 / 入职 / 培训 / 绩效 / 行政
乐奇桥（媒体不转写）──► 总控
                              │
入职 ──只读──► HCM（花名册与五部门进度）

定时任务 ──► 入职跟进
定时任务 ──► 月报看板
```
