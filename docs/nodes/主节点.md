# 主节点

独立机器上的一套 OpenClaw HR。职责：**用本机数据复跑测试已通过的流程，并沉淀记忆。** 审过的记忆包再推到 [备节点](备节点.md)。代码从 git 拉，不从 [测试节点](测试节点.md) 拷记忆。

另两份：[备节点](备节点.md) · [测试节点](测试节点.md)

## 能干什么

- 拉测试节点合入的 Skill / 脚本 / 文档，用**主节点自己的**花名册与演示数据复跑。
- 人审只挡**写入 `MEMORY.md`**：yaml 用 `storage.mode: separate`，不自动拼长期记忆；要点手工合并。
- **所有** workspace 的做梦报告都要进长期记忆（招聘 / 入职 / 培训 / 绩效 / 行政 / 路由 / main），所以合并质量要严。
- 飞书用本节点自己的应用。
- 月报走本机宿主机日检，不经飞书 Agent。

当前演示人：员工1（入职 cancelled）。**未冻结**，招聘侧会再补员工2 起的简历，入职状态后跑。不要把测试夹具灌进本机花名册。

## 不能干什么

- 不把测试节点的 `memory/`、`MEMORY.md`、`memory/*.sqlite`、`agents/*/sessions/` 拷过来。日记只来自这次复跑。
- **备节点第一次全量复制完成之前，不要开 dreaming。** 开着做梦再拷，备节点会接到写到一半的记忆。
- 不把本机 `env.sh` / Gateway token 推到备节点（备节点用自己的飞书应用和 token）。
- 不要用关 heartbeat 当停机：heartbeat 不是存活探测（见下）。

## 工作流程（你在这条链上的位置）

```text
其它内容落地（脱敏、演示数据等）
    ▼
备节点第一次全量复制（此时做梦必须关）
    ▼
主节点打开 dreaming + session-memory（separate，不自动改 MEMORY.md）
    ▼
复跑（会话 + 日记）→ 旁路报告
    ▼
人审要点 ──不通过──► 改报告 / 纠正事实 / 再问一轮 ──► 再审
    │
    通过 → 手工合并进该 workspace 的 MEMORY.md
    ▼
之后同步：全量再拷，或只拷记忆相关
```

复跑不是再点一次脚本就结束。deep 要不同查询、多次召回才会 promote；在主节点用多角度提问，才是沉淀。测试跑通只保证错流程不上来。

## 人审不通过

默认是**改，不是回退**。`separate` 下报告还在 `memory/dreaming/`，检索能搜到没关系；`MEMORY.md` 还没被这次 dream 改掉：

1. 改报告正文、删掉夹具/空跑/和花名册矛盾的段落，或让 Agent 按审意见再跑一轮。
2. 再审。通过后手工合并进 `MEMORY.md`。
3. 这一轮不要把未合并的 `MEMORY.md` 当成已批准长期记忆。

**快照回滚**只在已经写坏本机长期记忆时用：`MEMORY.md` 或 sqlite 已被错误 promote 改掉，改报告救不回来。那是事故退路，不是审不通过的常规动作。

## 给备节点

路径相对 `$OPENCLAW_STATE_DIR`（本机 `/opt/openclaw-hr/.openclaw-hr`）：

| 何时 | 拷什么 |
|------|--------|
| **第一次部署** | 做梦关着，**全量**复制主节点业务与工作区（花名册、人才库、Canvas、Skill 数据、空的或未开做的记忆）。`env.sh`、Gateway token、yaml 绝对路径、飞书 app **不要原样用主节点的**，备节点自己改。 |
| **之后** | 可以再全量拷，或只拷记忆：`MEMORY.md`、`workspace-*/memory/`、`memory/*.sqlite`。 |

不要对正在写入的目录做持续 rsync。第一次全量必须在做梦关闭时做。

## 本机配置

| 项 | 要求 |
|----|------|
| dreaming | **已开**。每天 23:00 `Asia/Shanghai`（`frequency: "0 23 * * *"`），`storage.mode: separate`。改点改 frequency 后重启 Gateway |
| session-memory | **已开**，与 dreaming 一起保持 |
| 嵌入 | `Qwen/Qwen3-Embedding-0.6B`，1024 维（与备、测相同，否则 sqlite 无法给备节点用） |
| 飞书 | 自己的应用；不要把同一个 app 填进另一台 Gateway |
| yaml 路径 | 本机绝对路径，不要提交测试机路径 |
| heartbeat | 可保持默认。它是定时读 `HEARTBEAT.md`，没事回 `HEARTBEAT_OK`。存活看 `hr-service.sh` / `GET /health`。业务域空 `HEARTBEAT.md` 会 skip。 |

## 记忆闸（已落地，做梦已开）

只挡写入 `MEMORY.md`。日记和做梦报告不隔离。合并前进 `MEMORY.md` 时手跑关键词体检即可。详表见 [`/opt/hr-ops/README-memory-gate.md`](/opt/hr-ops/README-memory-gate.md)。

```bash
/opt/hr-ops/memory-snapshot.sh
/opt/hr-ops/dream-report-gate.sh                 # 原地扫报告关键词
# /opt/hr-ops/dream-report-gate.sh --check <报告或 MEMORY.md>
# 人把要点手工合并进 MEMORY.md
# /opt/hr-ops/dream-report-gate.sh --memory      # 可选：扫已写入的 MEMORY.md
```

`separate` = 做梦不自动改 `MEMORY.md`。检索能搜到 `memory/` 里的日记和报告，这是预期。
