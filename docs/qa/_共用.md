## 拷贝与环境（容易踩）

1. 放到 `~/openclaw-hr/`（路径不同则改 `env.sh` 与 `openclaw.yaml`，见部署指南第五、六节）。
2. 若拷贝里带着负责人的 `env.sh`：**删掉或整文件改成自己的 Key**，再 `source`。
3. Skill 脚本（评分、人才库、月报、360、画像）需要 profile 根目录  
   `~/openclaw-hr/.openclaw-hr/requirements.txt`（含 pandas 等）。**只装 HCM backend 那份不够。**
4. 本机已有 Gateway 占用 `18790` 时，不要再起一个；先 `curl http://127.0.0.1:18790/health`。
5. CLI 需要 **Node ≥ 22.16**，且 PATH 含 `install/node_modules/.bin`（见部署指南）。

开测自检（全员）：

```bash
source ~/openclaw-hr/.openclaw-hr/env.sh
curl -sS http://127.0.0.1:18790/health
# 期望含 "ok":true 且 status live
node --version   # v22.16+
```

HCM（入职组必做，他人交叉时按需）：

```bash
curl -sS http://localhost:8000/api/health
# 期望 {"ok":true,"service":"hcm"}
```

## 对话与「怎么算路由对」

```bash
source ~/openclaw-hr/.openclaw-hr/env.sh
openclaw agent --agent router -m "……"
```

**通过信号（要能红/绿，不要凭感觉）：**

- 回复里明确点名子 Agent id：`recruitment` / `onboarding` / `training` / `performance` / `er-admin`。
- 忽略开头的 `plugins.allow is empty...`（可记 P3，不挡主路径）。
- **连续多条对话会串台**：上一条子 Agent 的回传可能混进下一条。测纯路由时：等上一条结束；或话术末加「先只说明交给哪个 agent id，不要展开执行」。
- **路由对 ≠ 业务做成**：人才库只有张磊时，相似检索会失败，但分给 `recruitment` 仍算路由通过。

会话排障（不要贴 Key）：`~/openclaw-hr/.openclaw-hr/agents/<agentId>/sessions/`

## 缺陷怎么写（复制这段）

```
标题：[<域>] <一句话现象>
级别：P0 / P1 / P2 / P3
Agent / Skill：如 router；recruitment / scoring-candidates

发生了什么：
期望：
复现：
1.
2.
3.

证据：退出码 / 文件是否存在 / 回复摘录（打码）/ 会话目录名
是否稳定：每次 / 偶发（第几次才出现）
```

级别：P0 起不来或路由进错域；P1 主路径失败或假成功；P2 展示/偶发；P3 体验。

过程类标签：`过程/绕圈` `过程/假成功` `过程/代批` `过程/合规`。

**绕圈：** 同一工具 + 实质相同参数连续失败 ≥3 次且无新策略。

**假成功（各域都要测，不是只有总控）：** 回复里出现「已完成 / 已生成 / 已排序 / 已出看板 / 已出月报」时，必须马上对照磁盘或 API。对不上记 **P1**，标签 `过程/假成功`。允许「明确失败」；不允许空口完成。对照物写在各角色文档的 `*-16` 一类用例和 `*-PROC-01`。
