# 验收清单 · 总控缺陷（修完后组员跑）

> 来源：[缺陷表/总控缺陷表.md](./缺陷表/总控缺陷表.md) · 规则见 [_共用.md](./_共用.md)  
> 勾选：**☑ 通过** · **☒ 未通过** · **☐ 未测 / 修前勿填通过**

## 流程

```
总控修 P1（及清单里要关的项）
        ↓
组员按本清单原话 / 原命令复测
        ↓
全过 → 本周测试 + 修复结束
有不过 → 总控再修，同一清单再跑，直到过
```

**修复合入之前：** 本清单只是验收标准与示范格式，可以预习命令。  
**禁止**在未合入修复时把 D-011 / D-012 / D-014 当「今日任务」去改磁盘、清 stub、或假填 ☑。

**修完之后：** 组员才执行本清单；**通过 = 收口**（不再开新用例、不再扫三日任务）。

## 铁律

- 禁止粘贴 API Key；会话只记 `agents/<id>/sessions/<uuid>` 前缀。
- 破坏性条（D-011）测完**必须还原**。
- 对话用独立 `--session-id`；纯路由可加「先只说明交给哪个 agent id，不要展开执行」。
- 模型抖动：失败先**原话再跑 1～2 次**；两次不同记 P2 偶发，不要升 P0。

### D-002 · P3 · `exec-approvals.json` socket 指向 `/root/...`

| | |
|--|--|
| 动作 | 读 `.openclaw-hr/exec-approvals.json` 的 `socket.path`，对比 `$HOME`；在 `openclaw.yaml` 搜 `approvals` |
| 过 | socket 与本机 `$HOME` 一致；**或**仍未启用审批且对话不空等 |
| 不过 | 已启用审批却仍连 `/root/...` 导致空等 |
| 证据 | `socket.path` 字符串（不要记 token）；yaml 有无 approvals |

**注意：** 组员只确认，不要擅自改 socket 文件。

## 修完之前组员可干什么（避免闲着、避免抢修）
