## 产品缺陷

### R-D-001

标题：[招聘][R-05/R-06] scoring-candidates 与 auditing-numbers 调用 deepseek-v4-pro 推理模型时 max_tokens 不足，content 为空致 JSON 解析失败
级别：P1
Agent / Skill：recruitment / scoring-candidates、auditing-numbers
过程标签：无（非假成功/绕圈，脚本明确报错退出码 1）

发生了什么：
`score_candidate.js`（R-05）与 `audit_numbers.js`（R-06）均硬编码使用 `deepseek-v4-pro` 推理模型，且 `maxTokens` 分别为 2500 和 2000（audit 另有一处 2500）。该模型把大量 token 消耗在 `reasoning_content` 上（实测单次推理约 2324 tokens），留给 `content` 的 token 近乎为 0，返回空 content + `finish_reason=length`，`extractJson()` 解析空串报 "Unexpected end of JSON input"，两脚本均以退出码 1 失败。

期望：
R-05 评分成功（0–100 分 + A/B/C/D），R-06 回核完成产出结论，均退出码 0 并写出 ranking JSON。

复现：
1. `source ~/openclaw-hr/.openclaw-hr/env.sh && cd ~/openclaw-hr/.openclaw-hr/workspace-recruitment`
2. R-05：`node skills/scoring-candidates/scripts/score_candidate.js scoring/clean-员工1-后端开发.json jds/jd-bigtech-后端开发工程师.md scoring/ranking-员工1.json`
3. R-06：`node skills/auditing-numbers/scripts/audit_numbers.js scoring/ranking-员工1.json inbox/员工1-后端开发.md scoring/ranking-员工1-audited.json`

证据：
- R-05 退出码 1；stderr「❌ 评分失败：LLM 返回 JSON 多次无法解析：Unexpected end of JSON input」
- R-06 退出码 1；stdout「数字回核 · 员工1：评分文字共抽取 37 个数字，简历比对存疑 8 个」→「❌ 数字回核失败：数字回核判定阶段失败：Unexpected end of JSON input」
- 直接调 API 验证：`reasoning_content` 长度 2324、`content` 为空、`finish_reason=length`；将 max_tokens 提到 8000 后 content 正常返回。

失败后磁盘状态：
目标输出路径 `scoring/ranking-员工1.json`、`scoring/ranking-员工1-audited.json` **不存在**（无半成品残留）。`scoring/results/ranking-员工1-后端开发.json`（2673B，7/31）等为历史成功产物，与本次失败无关。

是否稳定：每次（R-05 连续 3 次均失败；R-06 每次失败）

### R-D-002（环境/账户问题，非产品缺陷）

标题：[招聘][R-08] DashScope text-embedding-v3 返回 403（账户欠费/未开通），embedding 阶段失败
级别：环境/账户问题（不计入产品缺陷）
Agent / Skill：recruitment / ingesting-talent-pool
过程标签：无

发生了什么：
`ingest_talent_pool.py all` 的 embed 阶段调用 DashScope `text-embedding-v3`，连续 3 次重试均返回 HTTP 403。直接调 API 验证：默认端点返回 `AccessDenied.Unpurchased`（模型未开通），标准端点返回 `Arrearage`（账户欠费）。此为账户/计费问题，非代码缺陷。

期望：
账户充值或开通 `text-embedding-v3` 后，向量化成功，`talent-pool/talent-pool.json` 落盘。

复现：
1. `source ~/openclaw-hr/.openclaw-hr/env.sh && cd ~/openclaw-hr/.openclaw-hr/workspace-recruitment`
2. `python3 skills/ingesting-talent-pool/scripts/ingest_talent_pool.py all`

证据：退出码 1；stderr「embedding 批 0 重试 1/2/3: HTTP Error 403: Forbidden」→「RuntimeError: embedding 批 0 失败」。
是否稳定：每次

### R-D-003

标题：[招聘][R-08] ingest_talent_pool.py 只匹配 inbox/resume-*.md，夹具 员工1-后端开发.md 不被识别
级别：P3
Agent / Skill：recruitment / ingesting-talent-pool
过程标签：无

发生了什么：
脚本 stage_parse 用 `glob.glob(os.path.join(INBOX, "resume-*.md"))` 匹配简历，但测试夹具为 `inbox/员工1-后端开发.md`，文件名不带 `resume-` 前缀，导致发现 0 份简历。本次因 `parsed-all.json` 已有缓存数据未阻塞，但首次入库或新增简历时会漏抽。

期望：
脚本能识别 inbox 下所有简历 md（或夹具命名与脚本约定一致），首次入库可正常抽取。

复现：
1. 确保 inbox 只有 `员工1-后端开发.md`，无 `resume-*.md`
2. 删除 `talent-pool/parsed-all.json`
3. `python3 skills/ingesting-talent-pool/scripts/ingest_talent_pool.py parse`

证据：stdout「[parse] 发现 0 份简历」。
是否稳定：每次
