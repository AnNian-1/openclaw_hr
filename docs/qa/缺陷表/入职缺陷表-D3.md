## D-010

标题：[入职/Skill] `onboarding-review.sh` 不存在的人未快速失败，exit=0 并落盘假 review  
级别：**P1**  
Agent / Skill：onboarding / `running-onboarding-review`  
过程标签：`过程/假成功`

发生了什么：`bash skills/running-onboarding-review/scripts/onboarding-review.sh 不存在的人 7 nonexist` 对明显不存在的候选人，脚本**未快速失败**，反而：(1) exit=0；(2) 声称「第 7 天跟进已执行」；(3) 落盘 `review-state/review-不存在的人-day7.json`（假产物）；(4) 5 节点全标「未就绪」但仍宣称完成。用户/Agent 会被误导认为操作成功。  
期望：对不存在的候选人快速失败，exit≠0，**不落盘任何 review 文件**，明确报告「候选人不存在 / 无工作流状态」。  
复现：
1. `cd ~/openclaw-hr/.openclaw-hr/workspace-onboarding`
2. `bash skills/running-onboarding-review/scripts/onboarding-review.sh 不存在的人 7 nonexist`
3. 观察：exit=0，`review-state/review-不存在的人-day7.json` 被创建，输出「第 7 天跟进已执行」

证据：脚本输出含「Review 结论：第 7 天跟进已执行」；文件 `review-state/review-不存在的人-day7.json` 真实落盘；exit=0。测试后已手动删除假产物。  
是否稳定：每次（当前脚本无候选人名校验逻辑）

## D-011

标题：[路由] 混域2 中 er-admin 被分配"修改劳动合同"而非 onboarding，可能越权  
级别：P3  
Agent / Skill：router → er-admin / onboarding

发生了什么：混域测试「给测试员出培训又改合同」中，router 并行派发 `training`（出培训）+ `er-admin`（改合同）。按职责分工，修改劳动合同应归属 `onboarding`（入职域），而非 `er-admin`（行政政策域）。路由点名 `er-admin` 虽满足「点名子 Agent」的绿灯，但可能导致 er-admin 尝试执行超出其 skill 范围的操作（合同修改）。  
期望：router 能正确识别「修改劳动合同」归属 `onboarding`，或将合同类操作路由到正确的域。当前路由按关键词模糊匹配到 `er-admin`，存在业务归属错误。  
复现：
1. `openclaw agent --agent router -m "给测试员出一份入职培训材料，然后修改他的劳动合同状态"`
2. 观察：router 派发 `training` + `er-admin`，其中 er-admin 承担"修改劳动合同"

证据：router 回复「🔵 training — 出具入职培训材料；🔵 er-admin — 修改劳动合同状态」。  
是否稳定：每次（路由规则按关键词匹配）
