## D-002

标题：[总控] OpenClaw **exec 闸**（不是入职 Lobster 合同/账号门）  
级别：P3  
Agent / Skill：Gateway `exec-approvals`；本机 allowlist 只管 **recruitment**、**er-admin** 的 `exec`（包装脚本）。onboarding 人批走 `run-onboarding.sh` / lobster，不走此 socket。  
过程标签：无（未发生空等或代批）

这是什么：Agent 要在本机 `exec` 时，Gateway 用 `exec-approvals.json` + Unix socket 决定放行/拒绝/问人。本机 `ask: off`，不在名单则 deny，**不弹「请人批命令」**。D-011/D-012 靠 allowlist + 包装脚本，不靠这扇人批窗。

开测时（2026-08-26）：项目内 `.openclaw-hr/exec-approvals.json` 的 `socket.path` 曾为 `/root/.openclaw-hr/exec-approvals.sock`，与 `$HOME=/home/yhwz` 不一致。yaml 未开「问人审批」，对话未空等。

**2026-08-27 核对（登记，未再改文件）：**

- **Gateway 真源（正在用）：** `~/.openclaw/exec-approvals.json` → `socket.path` = `~/.openclaw/exec-approvals.sock`（对本机用户正确）。allowlist 也在这份。
- **项目副本（不是真源）：** `.openclaw-hr/exec-approvals.json` → 另一条 `.openclaw-hr/exec-approvals.sock`。组员不要拿它当 Gateway 配置。
- **参考 yaml / canvas README** 里仍有 `/root/.openclaw-hr/...` 示例，Gateway 不读这些当审批。

剩余风险：两份 json、两套 socket；若以后打开 `ask`，必须让 CLI 与 Gateway 连**同一** socket。原始「还指着 /root」在 live 上已过时。

期望：文档写明真源；启用问人审批时 socket 对本机 `$HOME`。  
复现（组员连本机请改对文件）：
1. 读 **`~/.openclaw/exec-approvals.json`** 的 `socket.path`（不要记录 token）
2. 对比 `$HOME`；可选对比项目内副本是否另一条路径
3. `openclaw.yaml` 搜 approvals（本机未开问人）

证据：2026-08-26 曾见 `/root/...`；2026-08-27 live 为 `$HOME/.openclaw/exec-approvals.sock`。PROC-08 未空等。  
是否稳定：双文件结构固定；`/root` 不再出现在上述两份 live json
