## §1 准备 (A.1-A.2):环境检查 + 独立 profile 隔离



### 1.1 目标

- **A.1** 摸清实操机现状(OS、Node、已装 OpenClaw、端口空闲情况)——4 项事实,不能假设
- **A.2** 创建一个**完全独立**的 profile `~/.openclaw-hr/`,与用户现有 `~/.openclaw/` 物理隔离



### 1.2 A.1 命令清单

```bash
# 1) 系统与运行时版本                                   
node --version                             # Node 版本
npm --version                              # npm 版本

# 2) 机器上已有的 OpenClaw
which openclaw                             # 二进制位置
openclaw --version                         # 当前用户级版本

# 3) 关键端口空闲情况
sudo lsof -iTCP:18789 -sTCP:LISTEN         # 默认 gateway 端口
sudo lsof -iTCP:18770 -sTCP:LISTEN         # 本课 HR Gateway 计划端口
```



### 1.3 A.1 预期输出与判定


| 输出示例                         | 解读                                  | 通过标准                                      |
| ---------------------------- | ----------------------------------- | ----------------------------------------- |
| `macOS 26.4.1`(实操机)          | 落在安全区                               | ≤ 26.4 可用 v2026.5.12;> 26.4 需降级 v2026.5.7 |
| `v24.14.0` / `npm 11.9.0`    | 满足 OpenClaw 要求(需 Node ≥ 22.16 或 24) | ≥ 22.16 且 < 25 即可                         |
| `~/.npm-global/bin/openclaw` | 用户级 openclaw 在 npm 全局               | 注意路径(避开它)                                 |
| `2026.4.15`(用户级)             | 用户日用版本                              | **不可触碰**                                  |
| 两个端口 `lsof` 无输出              | 端口空闲                                | 至少 **18770 必须空闲**                         |


> **本课锁定三组事实**(写作这句时,在本课实操环境里采集):
>
> 1. OpenClaw 版本锁 `v2026.5.12`
> 2. HR Gateway 端口 `18770`
> 3. 用户原有环境 `2026.4.15` 不可触碰



### 1.4 A.2 命令清单

```bash
# 1) 一次性建出 profile 目录骨架(10 个子目录一次到位)
mkdir -p ~/.openclaw-hr/{config,state,workspace,agents,sessions,memory,hooks,plugins,install,logs}

# 2) 写出环境变量文件(env.sh) — 权限 600,因含 token
cat > ~/.openclaw-hr/env.sh <<'EOF'
export OPENCLAW_STATE_DIR="$HOME/.openclaw-hr"
export OPENCLAW_CONFIG_PATH="$HOME/.openclaw-hr/config/openclaw.yaml"
export OPENCLAW_GATEWAY_TOKEN="$(openssl rand -hex 32)"
export OPENCLAW_HR_BIN="$HOME/.openclaw-hr/install/node_modules/.bin/openclaw"
alias openclaw-hr="$OPENCLAW_HR_BIN"
EOF
chmod 600 ~/.openclaw-hr/env.sh

# 3) 激活 profile
source ~/.openclaw-hr/env.sh
echo "$OPENCLAW_STATE_DIR"                 # 应打印 ~/.openclaw-hr
```



### 1.5 A.2 预期输出与判定


| 输出                          | 解读                                       |
| --------------------------- | ---------------------------------------- |
| 无报错                         | mkdir 成功,10 个子目录建好                       |
| `/Users/<you>/.openclaw-hr` | `source` 后 `OPENCLAW_STATE_DIR` 正确指向独立目录 |
| `chmod: env.sh` 不报错         | 权限 600 落实(token 不被全局可读)                  |




### 1.6 A.1-A.2 验证清单


| 项                               | 命令                                       | 通过标准                                                                                 |
| ------------------------------- | ---------------------------------------- | ------------------------------------------------------------------------------------ |
| profile 骨架完整                    | `ls -la ~/.openclaw-hr/`                 | 看到 10 个子目录(config、state、workspace、agents、sessions、memory、hooks、plugins、install、logs) |
| env.sh 权限安全                     | `ls -la ~/.openclaw-hr/env.sh`           | 权限位 `-rw-------`(600)                                                                |
| 环境变量生效                          | `echo $OPENCLAW_STATE_DIR`               | 打印 `~/.openclaw-hr`                                                                  |
| 二进制别名生效                         | `which openclaw-hr`                      | 指向 `~/.openclaw-hr/install/node_modules/.bin/openclaw`                               |
| 切到独立 profile 后 `openclaw` 不影响全局 | `openclaw --version`(在 isolated shell 内) | 此刻若 openclaw 未装会报 command not found(env.sh 中 alias 指向不存在的二进制),**正常**                 |




### 1.7 §1 坑速查


| 坑                                   | 现象                   | 应对                                           |
| ----------------------------------- | -------------------- | -------------------------------------------- |
| `mkdir` 报 Permission denied         | 目标目录已有同名子目录或父目录无写权限  | 用 `ls -la ~/.openclaw-hr/` 检查;必要时 `chmod` 修正 |
| `source` 后 `OPENCLAW_STATE_DIR` 仍是空 | env.sh 没 source 或语法错 | 用 `bash -n env.sh` 校验语法后重新 source            |
| `openssl rand` 找不到                  | 系统未装 openssl         | 改用 `head -c 32 /dev/urandom                  |

### 2.5 A.4 命令清单(Gateway 配置 + 启动)



#### 第 1 步:写 4 个配置项(SecretRef 引用 token)

```bash
source ~/.openclaw-hr/env.sh
cd ~/.openclaw-hr

openclaw config set gateway.port 18770 --strict-json
openclaw config set gateway.mode local
openclaw config set gateway.auth.token \
  --ref-provider default --ref-source env --ref-id OPENCLAW_GATEWAY_TOKEN
openclaw config set gateway.auth.mode token
```

> **关键解读**:`gateway.auth.token` 不是明文,而是 SecretRef(`--ref-source env --ref-id OPENCLAW_GATEWAY_TOKEN`)。配置文件中没有明文 token,值从环境变量取。**这是工业级配置的安全惯例**。



#### 第 2 步:收紧目录权限并跑 doctor --fix

```bash
chmod 700 ~/.openclaw-hr
openclaw doctor --fix --non-interactive --no-workspace-suggestions
```

> **doctor 跑起来 ≥90 秒**——不要中途 `Ctrl+C`,看到疑似"卡住"是正常的。

预期日志关键一行:`Plugins Errors: 0`(阶段 A 检查点硬条件)

#### 第 3 步:启动 Gateway

```bash
mkdir -p ~/.openclaw-hr/logs
cd ~/.openclaw-hr
nohup openclaw gateway run --port 18770 > ~/.openclaw-hr/logs/gateway.log 2>&1 &
echo $! > ~/.openclaw-hr/gateway.pid
sleep 3                                              # 给启动留出时间
cat ~/.openclaw-hr/logs/gateway.log | grep -E "ready|error"
```



#### 第 4 步:验证 /health

```bash
# 先 unset proxy(避免被拦)
unset http_proxy https_proxy all_proxy HTTP_PROXY HTTPS_PROXY ALL_PROXY

# 公开端点 —— 应返回 live
curl -s --noproxy '*' http://127.0.0.1:18770/health
# 预期:{"ok":true,"status":"live"}
```



### 2.6 A.4 预期输出与判定


| 输出                                       | 判定                       |
| ---------------------------------------- | ------------------------ |
| `{"ok":true,"status":"live"}` 且 HTTP 200 | ✅ Gateway 跑通             |
| `connection refused`                     | Gateway 未启动 / 端口错        |
| HTTP 502                                 | 被本机 HTTP 代理拦截(unset 后重试) |




### 2.7 §2 坑速查


| 坑                                              | 现象                                     | 应对                                                                                    |
| ---------------------------------------------- | -------------------------------------- | ------------------------------------------------------------------------------------- |
| `npm install` 覆盖了用户全局版本                        | 用了 `npm install -g openclaw@2026.5.12` | **严格本地安装**,绝不 `-g`                                                                    |
| `doctor` 跑得慢 + 弹交互                             | 不加参数                                   | 加 `--non-interactive --no-workspace-suggestions`,耐心等 ≥90 秒                            |
| `doctor` 警告"检测到多个 state 目录"                    | 同时存在 `~/.openclaw` 和 `~/.openclaw-hr`  | **这条警告要忽略**——两个 state 目录正是隔离目标                                                        |
| Gateway 启动日志含 `gateway.auth.token is inactive` | secrets surface 未激活                    | loopback + CLI 模式可忽略,飞书 Channel 接入时再处理                                                |
| `/health` 返回 HTTP 502                          | 本机配置了 `http_proxy`                     | `unset http_proxy https_proxy all_proxy ...` 或 `curl --noproxy '*'`                   |
| `nohup` 启动后进程消失                                | 终端会话关闭                                 | `gateway run` 启的是前台进程,会话或重启后会消失;每次接着做实验前 `ps -p $(cat ~/.openclaw-hr/gateway.pid)` 检查 |




### 2.8 §2 自测脚本

```bash

```

## §3 可观测 (A.5):Prometheus 端点 + OTel 推流配置



### 3.1 目标

- 装 `@openclaw/diagnostics-prometheus`、`@openclaw/diagnostics-otel` 两个插件
- 配置 OTel 推流 endpoint(4318 标准端口)
- **真验**:Prometheus 端点"无 token 拒 / 带 token 放"两种状态都过



### 3.2 命令清单



#### 第 1 步:装两个诊断插件

```bash
source ~/.openclaw-hr/env.sh
openclaw plugins install @openclaw/diagnostics-prometheus
openclaw plugins install @openclaw/diagnostics-otel
openclaw gateway restart
openclaw plugins list | grep -i diagnostics
```



#### 第 2 步:验证 Prometheus 端点

```bash
unset http_proxy https_proxy all_proxy HTTP_PROXY HTTPS_PROXY ALL_PROXY

# 公开 health 端点 —— 应返回 live
curl -s --noproxy '*' http://127.0.0.1:18770/health

# 无 token 访问 Prometheus —— 应被拒
curl -s --noproxy '*' -i http://127.0.0.1:18770/api/diagnostics/prometheus | head -1
# 预期:HTTP/1.1 401 Unauthorized

# 带 token 访问 Prometheus —— 应返回指标
curl -s --noproxy '*' -H "Authorization: Bearer $OPENCLAW_GATEWAY_TOKEN" \
  http://127.0.0.1:18770/api/diagnostics/prometheus | head -20
```



#### 第 3 步:写 OTel 推流配置


## §6 权限分级 (A.8):Per-Sender + Per-Agent Tool Policy + 硬证据



### 6.1 目标

- 三档 Per-Sender Tool Policy 写入并通过 config validate
- 三档 Per-Agent Tool Policy 写入(用 `config set` 单点写,**绝不** `config patch`)
- **可测量证据**:不同身份算出的有效工具集是 **10 / 6 / 4 / 3** 四档



### 6.2 第 1 步:打开 OpenClaw 真实 schema 兜底

> **不要照搬任何"推断 / 待验证"的资料**——OpenClaw 自带 schema 比文档更权威。

```bash

# 预期:0

# 验证 2:真实 key 是 toolsBySender
grep -n 'toolsBySender' /tmp/oc-schema.json | head -5
```



### 6.3 第 2 步:摸清 `toolsBySender` 三个层级


| 层级          | 配置路径                                  | 作用范围         | 本课是否使用          |
| ----------- | ------------------------------------- | ------------ | --------------- |
| 全局层         | `tools.toolsBySender`                 | 所有 Agent 共享  | ✅               |
| per-agent 层 | `agents.list[].tools.toolsBySender`   | 单个子 Agent    | ❌(本期不覆盖)        |
| channel 层   | `channels.<feishu/...>.toolsBySender` | 某个 channel 内 | ❌(本课没接 channel) |


```bash
grep -c '"channels":' /tmp/oc-schema.json        # 看 channel 层定义数量
# 预期:有
```



### 6.4 第 3 步:摸清 sender key 格式(5 种前缀 + 通配)

sender key 匹配**从最精确到最宽松**:

```
channel:<channelId>:<senderId>   ← 最精确(要求有 channel)
id:<senderId>                    (channel 用户 ID)
e164:<手机号>                     (E.164 标准手机号)
username:<用户名>
name:<显示名>                     ← 本课用的方式(没有飞书 channel 时)
*                                 ← 兜底
```

**两条关键规则**:

1. **先命中先用**(最精确匹配优先)
2. `deny` **永远赢**(安全默认)



### 6.5 第 4 步:写 Per-Sender patch 文件

```bash
cat > /tmp/hr-persender.patch.json5 <<'EOF'
{
  tools: {
    toolsBySender: {
      "name:HR主管":   { allow: ["*"] },
      "name:业务负责人": {
        allow: ["group:memory","group:web","read","sessions_list","sessions_history"],
        deny:  ["group:runtime","write","edit","apply_patch"]
      },
      "name:普通员工":   {
        allow: ["group:memory"],
        deny:  ["group:runtime","group:fs","browser","cron"]
      },
      "*":               { deny: ["*"] }
    }
  }
}
EOF

source ~/.openclaw-hr/env.sh

# 1) 先 dry-run 看 patch 要改几处
openclaw config patch --file /tmp/hr-persender.patch.json5 --dry-run

# 2) 真正写入
openclaw config patch --file /tmp/hr-persender.patch.json5

# 3) 校验
openclaw config validate
# 预期:validate 通过,无 schema 错误
```



### 6.6 第 5 步:写 Per-Agent policy(用 `config set` 单点)

> **绝对不能用** `config patch` **含** `agents.list`——数组会被整体替换,6 子 Agent 全没。

```bash
source ~/.openclaw-hr/env.sh

# 按 agents.list 实测索引:[0] main, [1] recruitment, [2] onboarding,
# [3] training, [4] performance, [5] er-admin, [6] router
```

### 6.7 第 6 步:验证权限分级确实生效(可测量证据)

> **核心方法**:绕开 LLM,**直接调用生产代码的** `applyFinalEffectiveToolPolicy` **函数**,构造 10 个探针工具,逐 Agent 算一次。

写 Node 脚本 `/tmp/verify-peragent-policy.mjs`:

```javascript
// /tmp/verify-peragent-policy.mjs
import { applyFinalEffectiveToolPolicy } from '<OpenClaw 内部模块>';

// 探针工具集:10 个
const probe = [
  'read', 'write', 'edit', 'apply_patch', 'browser',
  'exec', 'process', 'code_execution',   // group:runtime
  'sessions_spawn',                       // group:sessions
  'image_generate',                       // group:media
];

const agents = ['main', 'recruitment', 'onboarding', 'training',
                'performance', 'er-admin', 'router'];

for (const agent of agents) {
  const effective = applyFinalEffectiveToolPolicy({
    agentId: agent,
    sender:  'HR主管',                    // 必须传,否则命中 per-sender 兜底
    candidateTools: probe,
  });
  console.log(`${agent.padEnd(12)} -> ${effective.length} 个有效工具`);
}
```

跑出来应得到四档差异:


| Agent         | 有效工具数  | 解读                                   |
| ------------- | ------ | ------------------------------------ |
| `main`        | **10** | 没配 policy,拿全集                        |
| `router`      | **10** | `allow: ["*"]`,全集                    |
| `recruitment` | **6**  | `allow` 白名单外被过滤(runtime/browser 进不来) |
| `performance` | **4**  | `deny` 拦掉 runtime + 写文件              |
| `er-admin`    | **3**  | `deny` 额外禁掉 browser                  |


> **如果跑出来都是 0**:脚本没传 `sender: 'HR主管'`,per-sender 解析命中 `"*": { deny: ["*"] }` 兜底,所有工具被锁。**永远要显式传 sender** 才能看 per-agent 分级效果。
>
> 这个"传 sender 才能解锁"的副作用,反过来**也间接证明 per-sender 兜底机制是真正执行的**。

### 9.2 `config set` 写得进去 ≠ key 合法

> `config set` 只做轻量校验,**无效 key 也能写入**(如 `diagnostics.otel.captureContent`)。失效 key 会在严格的命令(如 `openclaw sessions`)才暴露。

**判断准则**:

- 以 `config schema` 输出 + 实测为准
- 不在 schema 里的 key,即便 `config get` 能读出,也**不要信任**它
