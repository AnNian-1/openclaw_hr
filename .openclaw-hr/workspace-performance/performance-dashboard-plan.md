## 二、可视化设计方案

### 2.1 整体架构

采用**单文件 HTML 自包含看板**（与现有个人 360 看板技术方案一致），分为四个核心模块：

```
┌─────────────────────────────────────────────────┐
│  合规声明 Banner（不评级、仅供 review）              │
├─────────────────────────────────────────────────┤
│  模块 A：部门整体绩效分布（S/A/B/C/D 占比）         │
├──────────────────────┬──────────────────────────┤
│  模块 B：各团队绩效对比 │  模块 C：同比环比趋势     │
├──────────────────────┴──────────────────────────┤
│  模块 D：360 反馈维度热力图（全员工 × 五维度）       │
├─────────────────────────────────────────────────┤
│  附录：数据说明 & 合规脚注                          │
└─────────────────────────────────────────────────┘
```

### 2.2 模块 A：部门整体绩效分布（S/A/B/C/D 占比）

**图表类型：** 环形图（Donut Chart）+ 人数标签

**设计思路：**
- 环形图展示 S/A/B/C/D 五档占比，中心显示总人数
- 每档用不同色阶：S-深绿、A-浅绿、B-蓝、C-橙、D-红
- 鼠标悬停显示该档具体人数和百分比
- 下方附柱状图，按团队分组展示各档人数堆叠

**数据来源：**
- ⚠️ **此模块依赖校准会最终确认的 S/A/B/C/D 评级结果**
- 当前 360 反馈聚合数据不包含绩效定级，需等校准会结束后从 HR 系统拉取
- 若评级数据未就绪，此模块显示「待校准会确认后更新」占位提示

**实现方案：**
```javascript
// 评级分布数据结构（示例，需从 HR 系统获取）
const ratingDistribution = {
  "S": { count: 2, pct: 8 },
  "A": { count: 8, pct: 32 },
  "B": { count: 10, pct: 40 },
  "C": { count: 4, pct: 16 },
  "D": { count: 1, pct: 4 }
};
```

### 2.3 模块 B：各团队绩效对比

**图表类型：** 分组柱状图（Grouped Bar Chart）

**设计思路：**
- X 轴：各团队名称（支付平台研发组、数据平台组、风控引擎组等）
- Y 轴：360 五维度综合平均分（1-5 分制）
- 每个团队一组柱子，分别代表五个维度
- 柱子上方标注具体分数
- 用虚线标注部门整体平均线，便于对比

**备选方案（评级数据就绪后）：**
- 堆叠柱状图：每个团队一个柱子，按 S/A/B/C/D 堆叠，直观展示各团队评级分布差异

**数据来源：**
- 主数据：各团队成员的 `aggregated-data.json` → `overall.*.average`
- 团队归属：从 `subject_role` 字段解析（如"支付平台研发组 后端开发工程师" → 支付平台研发组）

**当前可展示内容（基于 4 人模拟数据）：**

| 团队 | 成员 | 目标达成 | 专业技能 | 协作 | 责任心 | 成长 |
|------|------|---------|---------|------|-------|------|
| 支付平台研发组 | 张磊、李四 | 4.0 | 4.86 | 3.57 | 4.57 | 3.86 |
| 数据平台组 | 陈伟 | 4.0 | 4.14 | 4.14 | 4.14 | 4.0 |
| 风控引擎组 | 王芳 | 4.0 | 4.75 | 3.0 | 4.25 | 3.25 |

### 2.4 模块 C：同比环比变化趋势

**图表类型：** 折线图（Line Chart）+ 面积填充

**设计思路：**
- X 轴：时间周期（2025-H1 → 2025-H2 → 2026-H1，或季度粒度）
- Y 轴：部门整体 360 综合平均分
- 五条折线分别代表五个维度的趋势变化
- 用面积填充区分维度，增强视觉层次
- 标注关键节点（如组织架构调整、业务转型等事件）

**数据来源：**
- ⚠️ **此模块需要历史期次的聚合数据**
- 当前仅有 2026-H1 一期数据，无法绘制趋势线
- 需 HR 系统提供 2025-H1、2025-H2 等历史期次数据
- 若历史数据不可用，此模块显示「仅当前期次数据，趋势图待历史数据积累后启用」

**实现方案：**
```javascript
// 趋势数据结构（需多期次数据）
const trendData = {
  periods: ["2025-H1", "2025-H2", "2026-H1"],
  dimensions: {
    goal_achievement: [3.8, 3.9, 4.0],
    professional_skill: [4.2, 4.5, 4.6],
    collaboration: [3.5, 3.6, 3.4],
    responsibility: [4.0, 4.2, 4.3],
    growth: [3.5, 3.6, 3.6]
  }
};
```

### 2.5 模块 D：360 反馈维度热力图

**图表类型：** 热力图（Heatmap）

**设计思路：**
- 行：全体员工（按团队分组）
- 列：五维度（目标达成、专业技能、协作、责任心、成长）
- 颜色深浅代表分数高低（浅→深 = 低→高）
- 每个单元格标注具体分数
- 疑似分歧维度（极差 ≥ 1.0）加橙色边框标记

**数据来源：**
- ✅ **此模块可直接使用现有数据**
- 取各员工 `aggregated-data.json` → `overall.*.average`
- 分歧标记取 `divergence.*.suspected_split`

## 三、技术实现方案

### 3.1 技术栈

| 组件 | 选型 | 理由 |
|------|------|------|
| 图表库 | Chart.js 4.x（CDN） | 轻量、单文件可引入、支持响应式 |
| 热力图 | 原生 CSS Grid + 动态着色 | 无额外依赖，与现有看板风格一致 |
| 布局 | CSS Grid + Flexbox | 自适应不同屏幕尺寸 |
| 发布 | OpenClaw Canvas | 与现有个人看板一致的发布方式 |

### 3.2 数据流

```
HR 系统 API ──→ 评级数据 JSON ──┐
                                 ├──→ 数据聚合脚本 ──→ 看板 HTML
各员工 aggregated-data.json ────┘
各员工 aggregated-report.md ────→ 语义卡片
```

### 3.3 看板生成脚本设计

```bash
# 调用方式
bash scripts/build_department_dashboard.sh \
  feedback-360/source_feedback/ \
  --rating-data rating-2026-H1.json \
  --history-data history-trends.json \
  --publish --force

# canvas-id: performance-dashboard-2026-H1
# URL: http://127.0.0.1:18999/__openclaw__/canvas/documents/performance-dashboard-2026-H1/index.html
```

## 四、合规红线

1. **看板不含绩效评级结论**：S/A/B/C/D 仅展示校准会已确认的结果，看板本身不进行评级推断
2. **360 评分数据只取不算**：所有分数来自 `aggregated-data.json`，看板脚本不重新计算
3. **定位声明**：每个模块顶部标注「供绩效面谈与校准会 review 的输入材料」
4. **法律依据**：遵循《个人信息保护法》第 24 条及公司绩效管理制度第五条
