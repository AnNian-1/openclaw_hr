### 3.2 模块 A：绩效等级分布

**图表组合：** 环形图（主）+ 堆叠柱状图（辅）

**环形图设计：**
- 五档颜色：S(#059669) → A(#34d399) → B(#3b82f6) → C(#f59e0b) → D(#ef4444)
- 中心显示：总人数 + 参评率
- 悬停交互：显示该档人数、占比、代表性员工（脱敏）

**堆叠柱状图设计：**
- X 轴：各团队
- Y 轴：人数
- 每个柱子按 S/A/B/C/D 堆叠，直观对比团队评级结构差异
- 标注团队 S+A 占比（高绩效率）

**数据依赖：** ❌ 需校准会评级结果
**降级方案：** 数据未就绪时显示「待校准会确认后更新」占位卡片，附当前 360 综合均分参考值

- 疑似分歧维度（极差 ≥ 1.0）加橙色虚线边框 + ⚠️ 图标
- 鼠标悬停弹出详情：各视角分数明细 + 评语摘要

## 四、技术实现方案

### 4.1 技术栈

| 组件 | 选型 | 理由 |
|------|------|------|
| 图表库 | Chart.js 4.x（CDN） | 轻量、单文件可引入、支持响应式、动画丰富 |
| 热力图 | 原生 CSS Grid + JS 动态着色 | 无额外依赖，与现有个人看板风格一致 |
| 交互 | 原生 JS（无框架） | 保持单文件自包含，Canvas 发布友好 |
| 布局 | CSS Grid + Flexbox | 响应式，适配大屏投影和笔记本 |
| 发布 | OpenClaw Canvas | 与现有个人看板一致 |

### 4.2 数据流架构

## 五、合规红线

1. **看板不含绩效评级结论**：S/A/B/C/D 仅展示校准会已确认的结果，看板本身不进行评级推断
2. **360 评分数据只取不算**：所有分数来自 `aggregated-data.json`，脚本不重新计算
3. **定位声明**：看板顶部 Banner 标注「供绩效面谈与校准会 review 的输入材料」
4. **数据脱敏**：热力图中员工姓名可选脱敏模式（仅显示工号后四位）
5. **法律依据**：遵循《个人信息保护法》第 24 条及公司绩效管理制度第五条

## 七、风险与应对

| 风险 | 影响 | 应对策略 |
|------|------|----------|
| 校准会延期，评级数据不到 | 模块 A 无法展示 | 先用 360 综合均分做参考分布，标注「待确认」 |
| 参评人数不足 | 热力图/团队对比样本太小 | 明确标注样本量，不做统计推断 |
| 历史数据格式不兼容 | 趋势图数据对齐困难 | 编写适配层，统一转换为标准格式 |
| 评语质量低（模板化） | 语义卡片内容空洞 | 与模块 D 热力图联动，用数据驱动面谈话题 |

**关键原则：**
- 看板是 Pipeline 的**下游消费者**，不改变现有三层流程
- 个人看板（report.html）和部门看板（performance-dashboard）独立产出
- 部门看板的数据基准仍然是各员工目录下的 `aggregated-data.json`
