auditing-numbers 评测场景

评测驱动开发（方法基线 §五）：先建评测场景，测"没有 Skill 时的基线表现"，再写最小 SKILL.md，按观察迭代。
评测对象：对一份评分产出做数字回核——从评分文字（亮点/顾虑/评分理由/维度理由）抽出所有"数字+单位"，逐个反查候选人原简历，简历里对不上的交大模型判定是不是虚构，判为虚构的用最小替换对精确修正回原简历真实值，并留存修正前后快照。

== 评测场景 ==

场景 1 · 抓出真实的串台虚构数字
- 输入：张磊回核前评分结果 score-张磊-回核前.json（highlights[1] 与 dimension_reasons.抗压能力 都写了"58万笔/秒"）+ 张磊原简历 resume-tech-01-张磊-后端开发.md
- query：对这份评分结果做数字回核
- expected_behavior：
  - 抽出评分文字里所有"数字+单位"，逐个在原简历里反查
  - 抓出 2 处虚构——highlights[1] 和 dimension_reasons.抗压能力 都把简历的"12.8 万 TPS"写成了"58万笔/秒"
  - 给出最小替换对（bad_span=58万笔/秒 → good_span=12.8万 TPS），对两处做精确替换
  - 每处修正留存 text_before / text_after 两份快照
  - 产出回核报告：total_numbers / suspects / fabricated / fixes

场景 2 · 干净评分结果（边界，无虚构）
- 输入：一份评分文字里数字都能在原简历查到的评分结果 + 对应原简历
- query：对这份评分结果做数字回核
- expected_behavior：
  - 照常抽数字、逐个反查
  - 简历里能对上的、以及通用表述/约数/JD 场景数字 → 不判虚构
  - fabricated=0，fixes 为空，评分结果一字不改
  - 不误报、不报错，退出码 0

场景 3 · 回核基准只能是原简历，不能是 JD
- 输入：张磊回核前评分结果 + 张磊原简历（JD 里有"58万笔/秒"这个数字，简历里没有）
- query：对这份评分结果做数字回核
- expected_behavior：
  - 脚本只接收原简历作回核基准，不接收 JD
  - "58万笔/秒"在 JD 里有、在简历里没有——仍判虚构（基准是简历不是 JD）
  - 验证脚本签名只吃简历，不给 JD 留参数位——基准不可被污染

场景 4（边界）· 大模型判定调用偶发失败
- 输入：正常回核任务，但判定阶段大模型调用偶发网络中断/返回非法 JSON
- query：数字回核
- expected_behavior：
  - extract（抽数字）、verify（简历比对）两步是确定性的，不受影响
  - adjudicate（大模型判定）调用做 3 次重试 + 解析容错
  - 多次重试仍失败时显式报错、退出码非 0，绝不静默把"未判定"当"无虚构"放行
