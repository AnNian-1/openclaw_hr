scoring-candidates 评测场景

评测驱动开发（方法基线 §五）：先建评测场景，测"没有 Skill 时的基线表现"，再写最小 SKILL.md，按观察迭代。
评测对象：对一份脱敏后的候选人数据 + 岗位 JD，按 8 个固定维度评分（各 1-5 分）+ 综合匹配分（0-100）+ 评分理由 + 亮点顾虑 + 硬伤识别；批量时按综合分排序。

== 评测场景 ==

场景 1 · 单份强匹配候选人评分
- 输入：员工1脱敏 JSON（后端开发，13 年交易中台经验）+ 后端开发 JD
- query：对这位候选人按这个岗位评分
- expected_behavior：
  - 产出 8 个维度分（专业技能/经验匹配/逻辑能力/学习力/沟通能力/协作能力/抗压能力/价值观，各 1-5）
  - 综合匹配分 0-100、评级 A/B/C/D、评分理由、亮点、顾虑、硬伤字段
  - 员工1后端方向对口，专业技能/经验匹配两个高权重维度得分高
  - 评级带"建议"语气，不出现"淘汰/拒绝"

场景 2 · 批量评分一批候选人 + 排序
- 输入：一批脱敏候选人 JSON（方向有梯度：后端 + 算法/前端/数据等不对口方向）+ 后端 JD
- query：对这批候选人按这个岗位评分排序
- expected_behavior：
  - 每份候选人过完整评分，产出综合分
  - 全部评完按综合匹配分降序排序
  - 对口的后端候选人浮到前面，方向不对口的集中在后段，区分度清晰
  - 每个候选人标"建议动作"（建议进入面试/建议人工复核），不标"淘汰/通过"

场景 3 · 硬伤识别（反面样本）
- 输入：一份工作经历时间重叠的候选人脱敏 JSON（两段全职经历时间区间交叠）
- query：对这位候选人评分
- expected_behavior：
  - 8 维度照常打分（硬伤不影响维度评分本身）
  - hard_issues 字段抓出"工作经历时间矛盾"这个硬伤
  - 不直接淘汰——建议动作是"建议人工复核简历硬伤后再定"
  - 薪资高、城市不符这类岗位匹配度问题进 concerns，不进 hard_issues

场景 4（边界）· LLM 返回非法 JSON
- 输入：正常评分任务，但 LLM 偶发返回带尾逗号/非 JSON 的瑕疵输出
- query：评分
- expected_behavior：
  - 脚本对 LLM 返回做尾逗号容错 + 解析失败重试
  - 不因一次 LLM 输出瑕疵就让整次评分失败
  - 批量场景里单份失败显式标记"待人工处理"，不静默丢弃候选人
