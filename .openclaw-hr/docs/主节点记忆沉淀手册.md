# 主节点记忆沉淀手册

本机 2026-09-03 按现行脚本干跑通过。职责总览仍看 [主节点.md](主节点.md)。本文只写**闸怎么用**。

做梦**已开**：每天 23:00 `Asia/Shanghai`（`frequency: "0 23 * * *"`），`storage.mode: separate`；`session-memory` 为 `true`。改点只要改 yaml 里的 `frequency` 再重启 Gateway。不要 `promote --apply`。不要把测试节点的 `memory/` / `MEMORY.md` / sqlite / sessions 拷过来。

## 闸是两层，别混

| 层 | 什么 | 现在能不能用 |
|----|------|----------------|
| yaml | `plugins.entries.memory-core.config.dreaming.storage.mode: separate` | **开做梦时才写进 yaml**。deep 只把旁路报告写到 `workspace-*/memory/dreaming/<phase>/`，**不自动改** `MEMORY.md`。不要用 `inline` / `both`。 |
| 脚本 | `/opt/hr-ops/dream-report-gate.sh` | **现在就能用**。只扫关键词，**不挪文件、不代写 MEMORY.md**。 |

人审只发生在「把要点写进 `MEMORY.md`」那一步。日记和做梦报告留在 `memory/` 里、检索能搜到，是预期。

## 退出码（实测）

| 码 | 含义 |
|----|------|
| 0 | 无关键词，或没有可扫的文件 |
| 1 | 用法错误（例如 `--check` 的路径不是文件） |
| 2 | 命中关键词。**不要合并、不要当已批准长期记忆推备** |

关键词：`/opt/hr-ops/dream-gate-blocklist.txt`。本机追加（不入库）：`$OPENCLAW_STATE_DIR/ops/dream-gate-blocklist.local.txt`。

## 开做梦之前（当前）

闸仍然要会用，否则一开做梦就不知道先扫哪。

```bash
export OPENCLAW_STATE_DIR=/opt/openclaw-hr/.openclaw-hr

# 干跑（会打快照、造含「测试员」的假报告、再 restore）
/opt/hr-ops/dream-gate-selftest.sh

# 现在没有做梦报告时：
/opt/hr-ops/dream-report-gate.sh            # 「闸：memory/dreaming/ 无报告」→ 0
/opt/hr-ops/dream-report-gate.sh --memory   # 无 MEMORY.md → 0
```

本机 `dream-gate-selftest.sh` 已通过：含「测试员」的报告 `FLAG` 且退出 2；改掉关键词后 `OK` 且退出 0；`--check` / `--memory` 行为一致；文件留在原处，不会进 `ops/dream-quarantine`。

## 开做梦之后

yaml 已打开：`storage.mode: separate`，`frequency: "0 23 * * *"`（上海 23:00），`session-memory` 已开。然后：

```text
复跑（多角度提问，单次脚本不够 deep promote）
    ▼
旁路报告出现在 workspace-*/memory/dreaming/
    ▼
/opt/hr-ops/memory-snapshot.sh              # 合并前快照；打印快照目录
/opt/hr-ops/dream-report-gate.sh            # 扫全部做梦报告
    有 FLAG → 改正文，再扫，直到退出 0
    ▼
/opt/hr-ops/dream-report-gate.sh --check <这一份报告.md>
    ▼
人看要点，手工合并进该 workspace 的 MEMORY.md（脚本不代写）
    ▼
/opt/hr-ops/dream-report-gate.sh --check <该 MEMORY.md>
/opt/hr-ops/dream-report-gate.sh --memory   # 推备前再扫已写入的长期记忆
```

人审不通过：**改报告再审**，不要回滚。回滚只留给「`MEMORY.md` 或 sqlite 已经被写坏」的事故。

```bash
/opt/hr-ops/memory-snapshot.sh --list
/opt/hr-ops/memory-snapshot-restore.sh <STAMP> --yes
```

**Restore 只覆盖快照里有的文件，不会删后来多出来的 `MEMORY.md`。** 干跑若在快照之后新建了 `MEMORY.md`，restore 完要自己确认工作区没有残留（本次实测曾留下 17 字节的入职 `MEMORY.md`，已删）。

快照目录：`$OPENCLAW_STATE_DIR/ops/memory-snapshots/`（gitignore）。

## 命令速查

| 命令 | 作用 |
|------|------|
| `/opt/hr-ops/dream-gate-selftest.sh` | 干跑；通过打印 `selftest ok` |
| `/opt/hr-ops/memory-snapshot.sh` | 打一份，stdout 是快照路径 |
| `/opt/hr-ops/memory-snapshot.sh --list` | 列出 STAMP |
| `/opt/hr-ops/dream-report-gate.sh` | 扫 `memory/dreaming/**/*.md` |
| `/opt/hr-ops/dream-report-gate.sh --check FILE` | 合并前查一份 |
| `/opt/hr-ops/dream-report-gate.sh --memory` | 扫各 `MEMORY.md` |
| `/opt/hr-ops/memory-snapshot-restore.sh STAMP --yes` | 事故回滚 |

脚本入口说明也在 [`/opt/hr-ops/README-memory-gate.md`](/opt/hr-ops/README-memory-gate.md)。
