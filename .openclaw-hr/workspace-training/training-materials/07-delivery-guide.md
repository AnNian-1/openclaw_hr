## 一、物料清单

本培训包共包含 8 份物料文件，全部位于 `training-materials/` 目录下：

| # | 文件名 | 用途 | 目标用户 |

| 04 | `04-instructor-manual.md` | **讲师手册**（讲解要点、互动引导、控场提示）| 授课讲师 |
| 05 | `05-participant-handbook.md` | **学员手册**（课程速查 + 第一周行动清单）| 学员（课前发放）|
| 06 | `06-assessment.md` | 课后测试题（10 题 + 答案详解 + 对应矩阵）| 讲师 / HR |

### 物料之间的关系

```
01 需求分析 ─── 定义 T1-T5
    │
    ▼
02 课程设计 ─── 模块划分 + 对应矩阵
    │
    ▼
03 PPT 大纲 ─── 逐页展开 ←── 04 讲师手册  ← 讲解要点/互动/控场
    │                     ←── 05 学员手册  ← 速查+行动清单
```

## 二、培训前中后实施流程

### 2.1 培训前（T-14 天至 T-1 天）

| 时间 | 事项 | 负责人 |
|---|---|---|
| T-14 天 | 确认本期学员名单（岗位、入职时间、技术背景） | HR 招聘组 |
| T-14 天 | 确认讲师排期（HR OD&T + 算法/架构/产品讲师） | HR OD&T |
| T-10 天 | 讲师熟悉物料包（阅读 01-08，重点关注 04 讲师手册） | 全体讲师 |
| T-10 天 | 准备 PPT（根据 03-ppt-outline.md 制作正式 PPT） | HR OD&T |
| T-7 天 | 确认培训场地、投影、音响、WiFi / VPN | 行政 |
| T-5 天 | 为学员开通 GitLab 账号、模型 API Key 配额 | IT 支持 |
| T-3 天 | 向学员发放《学员手册》（电子版）及课前准备清单 | HR OD&T |
| T-2 天 | 讲师内部串讲：过一遍课件和实操流程（至少 1 次）| 全体讲师 |
| T-1 天 | 确认所有 Demo 环境/实操环境在培训机器上可运行 | 技术讲师 |
| T-1 天 | 打印物料（讲师手册、评估反馈表）、准备培训证书 | 行政 |

### 2.2 培训中（D-Day 1 ~ D-Day 2）

| 时间段 | 任务 | 负责人 |
|---|---|---|
| 第一天上午 | 模块 1：走进星桥科技（HR OD&T）| HR OD&T |
| 第一天上午 | 模块 2：产品体系与技术架构（产品总监/架构师）| 技术讲师 |
| 第一天下午 | 模块 3：开发环境搭建与规范（资深工程师）| 技术讲师 |
| 第一天下午 | 模块 4：大模型开发基础（前 90 min，算法工程师）| 技术讲师 |
| 第二天上午 | 第一天回顾 + 模块 4 续 + 模块 5：RAG 实战 | 技术讲师 |
| 第二天下午 | 模块 5 续 + 模块 6：优化与合规（算法负责人）| 技术讲师 |
| 第二天下午 | 课后测试 + 评估反馈 + 结班总结 | HR OD&T |

**注意事项**：
- 每个模块之间留 5 min 缓冲（学员休息、设备切换）
- 技术讲师准备"课间答疑"时间段（尤其实操环节）
- 每天中午午休前留 5 min 总结当天要点

### 2.3 培训后（T+0 至 T+30 天）

| 时间 | 事项 | 负责人 |
|---|---|---|
| T+0 天 | 收齐评估反馈表，统计评分数据 | HR OD&T |
| T+0 天 | 批改课后测试题，统计成绩与薄弱环节 | HR OD&T |
| T+3 天 | 输出培训总结报告（参训人数、测试均分、反馈评分、改进建议）| HR OD&T |
| T+7 天 | 将培训总结发送给参训学员的导师和部门主管 | HR OD&T |
| T+30 天 | 跟进学员第一周行动清单完成情况（HR 关怀沟通）| HR OD&T |
| T+90 天 | 与导师沟通学员入职 90 天表现（检验培训效果）| HR OD&T |

## 三、新讲师上手路径

如果你是新加入本课程的讲师（尤其是算法与数据部的技术讲师），以下路径可以帮助你快速上手：

### 3.1 1 小时快速了解

```
Step 1（10 min）: 读 01-needs-analysis.md → 了解受众和培训目标
Step 2（15 min）: 读 02-course-design.md → 了解整体课程结构和你的模块位置
Step 3（10 min）: 读 03-ppt-outline.md → 看你的模块对应的 PPT 内容
Step 4（20 min）: 读 04-instructor-manual.md → 你的模块的讲解要点 + 互动引导
Step 5（5 min）: 读 06-assessment.md → 了解测试题方向
```

### 3.2 讲师备课 Checklist

- [ ] 通读 01-08 全部物料（至少 1 遍）
- [ ] 重点精读 04 讲师手册中你负责的部分
- [ ] 跑通所有实操环节（从零开始走一遍代码，确保环境无误）
- [ ] 准备你自己的补充案例（如模块 4/5 的代码 Demo 示例、模块 6 的公司内部安全案例）
- [ ] 参加讲师串讲会（T-2 天）
- [ ] 确认设备（投影翻页笔、音响、无线麦克风）
- [ ] 提前加到培训学员群（提前了解学员技术背景）

### 3.3 常见备课误区

| 误区 | 正确做法 |
|---|---|
| 对着讲师手册逐字念 | 讲师手册是「讲解要点」，自然组织语言即可 |
| 在自己电脑上跑通的代码到了培训现场跑不通 | 提前到培训场地用培训设备跑一遍 |
| 学员问到的技术问题现场答不上来 | 准备一个「待办清单」，记下来课后回复 |
| 实操环节讲太多理论 | 实操环节"先动手再补充原理" |

## 四、培训当天 Checklist

### 4.1 培训前一天

- [ ] 确认场地空调、照明、桌椅就位
- [ ] 确认投影 + 讲师电脑连接正常 + 翻页笔电池
- [ ] 确认 WiFi / VPN 可正常访问（公司内网、GitLab、网关）
- [ ] 打印学员签到表、评估反馈表（或准备在线表单）
- [ ] 准备培训证书（已盖章、待填写学员姓名）
- [ ] 培训物料电子版放入讲师电脑桌面文件夹
- [ ] 确认学员群已建立，提前发培训提醒

### 4.2 培训当天 —— 开场前

- [ ] 提前 30 min 到场测试设备
- [ ] 打开 Demo 环境并验证可用
- [ ] 打印材料放置在每个座位上（学员手册、反馈表）
- [ ] 群内发消息提醒学员到场
- [ ] 准备好学员签到表

### 4.3 培训当天 —— 各环节

- [ ] 开班致辞 + 学员自我介绍（模块 1）
- [ ] 模块 2 产品 Demo 前再次确认 Demo 环境
- [ ] 模块 3 实操前确认所有学员环境就绪
- [ ] 模块 4-5 实操时安排助教巡回辅导
- [ ] 模块 6 案例研讨前打印案例说明
- [ ] 课后测试发放（闭卷）
- [ ] 评估反馈表填写（匿名，讲师离场）
- [ ] 合影 + 颁发培训证书

### 4.4 培训结束后

- [ ] 收回评估反馈表（或导出在线表单数据）
- [ ] 收集课后测试答卷
- [ ] 与各讲师做简短复盘（有什么需要改进的）
- [ ] 整理培训照片，发群里

## 五、常见问题处理预案

### 5.1 人数超员（超过 15 人）

| 问题 | 影响 | 处理方案 |
|---|---|---|
| 实操环节讲师无法逐一辅导 | 环境搭建慢的学员会掉队 | ① 增加 1-2 位助教（从算法与数据部抽调）<br>② 实操前发放更详细的分步骤指导文档<br>③ 按水平分组（基础相近的在一组）|

### 5.2 进度落后

| 情况 | 影响 | 处理方案 |
|---|---|---|
| 上午模块讲超时 15-20 min | 挤压下午实操时间 | ① 压缩 Q&A 时长（引导课后群内答疑）<br>② 模块 2 演示环节合并为 1 个 Demo（协同云 + 数据洞察一起演示）<br>③ 第二天回顾缩短至 5 min |
| 实操环节远超预期时间 | 模块 6 案例讨论时间不足 | ① 模块 6 案例三选一（保留与学员工作最相关的那个）<br>② 案例研讨的展示环节改为各组派代表快速口述（每组 2 min）|
| 第二天下午严重延时 | 测试和反馈没时间做 | ① 测试改为课后在线完成（但需 24 小时内提交）<br>② 反馈表二维码发给学员课后填写 |

### 5.3 设备故障

| 故障 | 处理方案 |
|---|---|
| 投影仪无法使用 | 提前准备：讲师电脑屏幕共享到学员群 + 大会议室自带的电视屏 |
| 网络中断（无法访问内网）| 技术讲师使用本地预先下载的 Demo 视频录制 + 离线版代码示例<br>实操环节改为"看讲师演示 + 自己理解代码逻辑" |
| VPN 不稳定 | 提前将代码和依赖打包成 Docker 镜像，学员本地运行 |
| 学员自带电脑配置不兼容 | 准备 2 台备用的公司笔记本，预装好全部开发环境 |

### 5.4 学员不参与 / 互动冷场

| 情况 | 处理方案 |
|---|---|
| 问答环节无人提问 | ① 讲师准备铺垫问题（如"你们最想了解公司的哪个方面？"）<br>② 采用"提前写便利贴"方式——发便利贴让学员写问题，讲师选答<br>③ 把问答变成小组讨论——各组讨论 3 min 后派代表提问 |
| 实操环节部分学员不动手 | ① 安排助教到这些学员身边主动询问<br>② 设置"第一个完成的小组/个人有奖励" |
| 案例讨论环节某组沉默 | ① 讲师坐到该组参与讨论<br>② 给出更具体的引导问题（"如果是你怎么解决这个问题？"）|
| 学员玩手机/注意力分散 | ① 增加互动频率（每 20 min 抛一个问题）<br>② 实操环节要求学员把代码结果展示出来 |

### 5.5 学员技术基础差异大

| 情况 | 处理方案 |
|---|---|
| 应届生跟不上代码实操 | ① 在实操开始前，安排 10 min 的"预备知识"讲解（如 Python 基础、HTTP 请求概念）<br>② 给基础薄弱的学员分配有经验的小组长 |
| 有经验学员觉得太简单 | ① 在实操环节设置 Extra Challenge（如加入 Hybrid Search、实现缓存策略）<br>② 请有经验的学员当"小组导师"帮助其他人（加深自己的理解）|

## 六、培训质量保障

### 6.1 课程持续改进

每次培训后收集以下数据并归档：

| 数据 | 来源 | 用途 |
|---|---|---|
| 课后测试平均分 | 06-assessment.md 批改结果 | 判断"学习层"是否达标（≥75%）|
| 评估反馈表综合评分 | 08-evaluation-form.md 统计 | 判断"反应层"是否达标（≥4.0/5）|
| 各模块评分明细 | 反馈表分项 | 识别需要改进的模块 |
| 开放问题反馈 | 反馈表问答 | 获取定性改进建议 |
| 讲师复盘记录 | 课后讨论 | 记录讲师视角的改进点 |

### 6.2 迭代周期

> 每期培训结束后 → 1 周内出总结报告 → 针对性问题修改对应物料 → 下一期培训前更新完成

---

> 💡 **一句话总结**：不要把 8 份物料丢给讲师就跑——07 交付指南就是让讲师知道"每个文件是干什么的、什么时候用、遇到问题怎么办"。提前串讲、提前跑通代码、提前准备预案——培训成功靠的是准备，不是临场发挥。
