# 01-需求分析：新员工培训 · AI 大模型应用开发岗位

> **AI 辅助生成，讲师审核后交付**

## 一、培训背景

星桥科技（北京星桥网络科技有限公司）成立于 2016 年，是一家专注于企业级 SaaS 与数据智能服务的互联网公司，主营「星桥协同云」与「星桥数据洞察」两条产品线。公司处于规模化增长阶段，研发与产品团队占比约 60%。

随着 AI 大模型技术的快速演进，公司正积极将大模型能力融入产品矩阵，提升智能化水平。为此，研发中心持续招募具备 AI 大模型应用开发能力的新员工，充实算法与数据部、后端研发部等技术团队。

本培训面向新入职的 AI 大模型应用开发岗位员工，目标是帮助他们快速融入公司、掌握必要的技术实践能力，缩短从入职到独立产出的过渡期。

## 二、目标受众画像

| 维度 | 描述 |
|---|:---|
| **岗位** | AI 大模型应用开发工程师（算法与数据部 / 后端研发部） |
| **数量** | 预计每批 5–15 人 |
| **技术背景** | 具有计算机科学、人工智能或相关专业本科及以上学历；熟悉 Python、了解深度学习基础；对 LLM 有一定实践经验或学习经历 |
| **工作经验** | 应届毕业生至 3 年经验不等 |
| **入职状态** | 已完成入职手续，首次接触星桥科技 |
| **学习风格** | 动手实践型偏好明显，对理论学习接受度高但更看重「能跑起来」 |

## 三、受众痛点

1. **公司信息散落在多份文档中**——新员工入职后需要分别阅读《公司简介》《入职流程》《培训与晋升》等文件，缺乏一站式全景视角，容易遗漏关键信息（如导师制、晋升评审周期等）。
2. **对公司的 AI 技术栈与数据资产不清楚**——新员工不确定公司使用的是哪些大模型平台、数据存储方案、API 网关或模型服务框架，来了之后不知道从哪开始写第一行代码。
3. **开发环境与规范不了解**——公司的代码仓库管理（GitLab / GitHub）、CI/CD 流程、代码审查规范、环境配置要求等对新员工来说是完全陌生的，上手前容易因为环境问题卡住。
4. **大模型应用开发的「落地」经验不足**——虽然具备理论基础，但真正在公司级产品中集成 LLM（提示工程、RAG、微调、安全合规、成本控制等）方面缺乏实践经验。
5. **不知道如何与现有产品体系对接**——「星桥协同云」「星桥数据洞察」的产品逻辑和 API 接口不清楚，大模型能力如何嵌入现有功能模块、数据流怎么走，缺乏端到端的理解。

## 四、培训目标（布鲁姆认知层次）

| 编号 | 目标 | 层次 |
|---|---|---|
| **T1** | 了解星桥科技的公司概况、组织架构、企业文化与价值观，能够准确说出公司使命和五大价值观 | 识记 |
| **T2** | 理解星桥科技的产品体系（协同云、数据洞察）和技术架构，能够说明大模型在公司产品中的定位与三种以上的典型应用场景 | 理解 |
| **T3** | 能够按照文档指引独立完成本地开发环境配置，包括代码仓库克隆、依赖安装、模型 API Key 获取与配置，并通过一个 Hello World 验证程序验证环境就绪 | 应用 |
| **T4** | 能够运用主流大模型 API（如 OpenAI / 国产大模型）与 RAG 框架完成一个包含「文档检索 → 生成回答」的端到端 Demo 开发 | 应用 |
| **T5** | 能够分析大模型应用在生产环境中的常见问题（如幻觉、延迟、成本、安全合规），并针对具体场景给出两种以上的优化策略 | 分析 |

## 五、约束条件

| 约束项 | 说明 |
|---|---|
| **培训时长** | 集中培训 2 天（共约 12 小时有效教学时间）|
| **培训形式** | 线下面授 + 现场实操，不设远程参与 |
| **硬件/环境** | 学员自带开发电脑，公司提供 GPU/API 配额及测试环境账号 |
| **师资** | 由算法与数据部资深工程师主讲技术模块，HR OD&T 主讲公司通识模块 |
| **培训时间** | 新员工入职首周完成公司级 Onboarding，入职首月内完成本技术培训 |

## 六、成功标准

| 维度 | 标准 |
|---|---|
| **反应层** | 培训反馈表综合评分 ≥ 4.0 / 5.0 |
| **学习层** | 课后测试平均得分 ≥ 75%（含 T1-T5 全覆盖） |
| **行为层** | 入职 90 天内完成至少一个与所在团队产品相关的小功能或 Demo 交付 |

> 成功标准参考柯氏四级评估模型的前三级设定。
