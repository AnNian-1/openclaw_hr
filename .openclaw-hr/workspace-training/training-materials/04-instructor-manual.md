### 模块 1：走进星桥科技（90 min）

> 讲师：HR OD&T 讲师
> 对应目标：T1

---

#### 幻灯片 1：封面（0.5 min）

| 项目 | 内容 |
|---|---|
| **讲解要点** | • 简单介绍自己与本次培训的背景<br>• 快速过封面信息（日期、主办方） |
| **互动引导** | 无（直接切入） |
| **讲师提示** | 封面页不要超过 30 秒，快速翻过即可 |

#### 幻灯片 2：开班致辞 + 自我介绍（10 min）

| 项目 | 内容 |
|---|---|
| **讲解要点** | • 请部门负责人简短致辞（3-5 min，提前沟通好内容）<br>• 讲清楚本次培训的目标：帮新员工「快速融入、能写第一行代码」<br>• 轮圈自我介绍：姓名 + 学校/上一家公司 + 一句话兴趣/期待（每人 30 秒） |
| **互动引导** | 「大家轮流介绍一下自己，包括你做过什么和 AI 相关的项目或学习经历」 |
| **讲师提示** | • 自我介绍环节容易拖时间，设好时间提醒<br>• AI 人员背景差异大，注意听他们提到过什么技术栈，后续技术讲师可以针对性调整细节 |

#### 幻灯片 3：模块 1 过渡页（0.5 min）

| 项目 | 内容 |
|---|---|
| **讲解要点** | • 简单说一下模块 1 涵盖公司概况、制度、发展路径<br>• 对应培训目标 T1——"了解公司" |
| **讲师提示** | 过渡页快速带过，1-2 句话即可 |

#### 幻灯片 4：公司发展历程（5 min）

| 项目 | 内容 |
|---|---|
| **讲解要点** | • 星桥科技 2016 年成立、总部北京中关村软件园<br>• 300 人规模，研发占 60%——这点可以强调：你们所在的研发团队是公司最大的部门<br>• B2B SaaS 定位，服务 8000+ 中小企业——讲一下客户类型（制造业、零售、服务业）<br>• B 轮融资背景——公司处于规模化增长期 |
| **互动引导** | 「有谁之前了解过我们的产品？使用过星桥协同云的同学举个手？」 |
| **讲师提示** | • 数字记清楚：「2016」「300 人」「8000 家」「5000 万」<br>• 如果座中有之前用过产品的学员，可以请他们分享体验 |

#### 幻灯片 5：使命与价值观（5 min）

| 项目 | 内容 |
|---|---|
| **讲解要点** | • 使命：「用数据智能让企业管理更高效」——你们的 AI 开发工作直接支撑这个使命<br>• 五大价值观逐条解读：<br>  - 客户第一：做 AI 功能时，对客户真实场景的理解比炫技重要<br>  - 务实诚信：给客户的 AI 输出要可信、可验证<br>  - 持续学习：这个领域变化最快，保持学习是刚需<br>  - 协作共赢：AI 不是孤立的，需要和产品、后端、测试紧密配合<br>  - 拥抱变化：模型选型、框架更迭——这是常态 |
| **互动引导** | 「五大价值观里大家觉得哪一条和 AI 开发关系最密切？为什么？」 |
| **讲师提示** | • 不要把价值观念一遍——每个价值观结合 AI 开发的场景解读<br>• 时间充裕可以多讲"持续学习"和"拥抱变化"——这对 AI 开发者最有共鸣 |

#### 幻灯片 6：组织架构（5 min）

| 项目 | 内容 |
|---|---|
| **讲解要点** | • 五大中心结构：研发、产品、商业化、职能、战略与运营<br>• 研发中心详细：后端研发部、前端研发部、算法与数据部（你们 AI 团队核心归属）、测试与质量部、运维与基础架构部<br>• 强调算法与数据部是 AI 大模型开发的主要阵地，但和后端、运维的协作非常密切 |
| **互动引导** | 「有谁知道算法与数据部的负责人是谁？（停顿一下）可以先记住，以后你们会经常打交道」 |
| **讲师提示** | • 快速过架构图即可，不需要每个部门展开<br>• 如果有最新组织架构调整，提前在 PPT 上更新 |

#### 幻灯片 7：新员工工作制度（5 min）

| 项目 | 内容 |
|---|---|
| **讲解要点** | • 工作时间与午休——可以轻松地说"不打卡，但团队站会和联调时间请准时"<br>• 研发岗每周 1 天远程——讲清申请流程<br>• 企业微信：公司统一 IM，所有审批、沟通都在上面<br>• 工号由 HR 分配，入职后注意保密 |
| **互动引导** | 「有谁已经加了企业微信？都加到群里了吗？」——确认沟通渠道就绪 |
| **讲师提示** | • 这个部分信息量大但枯燥，控制节奏<br>• 关键数字（时间、远程天数）让学员自己记笔记，不要念表 |

#### 幻灯片 8：培训与发展体系（8 min）

| 项目 | 内容 |
|---|---|
| **讲解要点** | • 四类培训体系——入职培训 → 专业/技术培训和管理者培训是你门未来重点<br>• 双通道职级：P 通道（专业）和 M 通道（管理），两条通道等效<br>• P 通道路径：P3（初级）→ P4（中级）→ P5（高级）→ P6-P8（资深/专家/首席）<br>• 晋升条件：在本职级满规定时间 + 绩效 ≥ B 且至少 1 次 A + 能力达标 |
| **互动引导** | 「你们现在大多从 P3 或 P4 起步，想想两年后你们想达到哪个级别？」 |
| **讲师提示** | • 强调「不想带团队也能晋升」——技术人员最关心这点<br>• 不要全文叙述晋升流程，学员手册里有完整版<br>• 顺便提一下考证补贴——PMP、AI 相关认证等都可以申请报销 |

#### 幻灯片 9：导师制与 90 天路线图（7 min）

| 项目 | 内容 |
|---|---|
| **讲解要点** | • 入职即配 Mentor——由算法或后端的有经验同事担任<br>• 导师 3 个月带教期：业务指导、答疑、文化融入<br>• 90 天路线图：第 1 周 Onboarding → 第 1 个月部门培训 + HR 关怀 → 第 3 个月导师期结束 → 试用期满前 2 周转正<br>• 内推奖金——有合适人才记得推 |
| **互动引导** | 「大家已经有导师了吗？（等回应）如果没有，培训完后 HR 会安排对接」 |
| **讲师提示** | • 提前和 HR 确认好本期学员的导师分配情况<br>• 强调：导师不是保姆——主动请教是学员自己的责任 |

#### 幻灯片 10：HR 数字员工小慧（3 min）

| 项目 | 内容 |
|---|---|
| **讲解要点** | • 「小慧」是公司的 HR 数字员工，7×24 小时在线<br>• 企业 IM 内可直接咨询政策、查个人事务<br>• 报到当天会主动推送入职指引<br>• 复杂问题自动转人工 HR |
| **互动引导** | 「大家应该已经在小慧那里收到过推送了吧？没加上的举手，我让 HR 帮你对接」 |
| **讲师提示** | • 快速过，不展开 |

#### 幻灯片 11：模块 1 问答（15 min）

| 项目 | 内容 |
|---|---|
| **讲解要点** | • 开放问答——公司制度、团队情况、导师、转正、福利等都可以问<br>• 如果没人提问，可以抛一些问题引导：「大家有什么关于公司还不太清楚的？」「有没有人想知道研发中心的具体分工？」 |
| **互动引导** | 开放式提问，鼓励学员提问 |
| **讲师提示** | • 这个环节非常重要——新员工有很多问题但有时不愿第一个开口<br>• 准备一些铺垫问题以备冷场<br>• 不能当场回答的问题记下来，培训后找对应部门回复 |

### 模块 3：开发环境搭建与规范（90 min）

> 讲师：资深工程师（算法与数据部）

---

#### 幻灯片 21：模块 3 过渡页（0.5 min）

| 项目 | 内容 |
|---|---|
| **讲解要点** | • 现在动手——配置环境，跑通第一行代码<br>• 对应 T3——环境配置 + Hello World |
| **讲师提示** | 快过 |

#### 幻灯片 22：开发环境概览（5 min）

| 项目 | 内容 |
|---|---|
| **讲解要点** | • 必要软件：Python 3.10+、Git、Docker Desktop（有更好）<br>• 推荐：VS Code、pyenv / conda<br>• 提前确认：GitLab 账号、VPN（如果需要的话）是否已开通<br>• 课前检查清单表——让学员逐项自查 |
| **互动引导** | 「现在大家打开终端，输入 python3 --version，版本号低于 3.10 的请注意」 |
| **讲师提示** | • 实操环节最怕环境不一——课前先发一份环境准备邮件，让学员提前安装好<br>• 准备一个 U 盘或网盘链接备选——装有全部依赖的离线环境 |

#### 幻灯片 23：代码仓库与权限（5 min）

| 项目 | 内容 |
|---|---|
| **讲解要点** | • GitLab 内网地址（提前写在白板或发到群里）<br>• SSH Key 配置步骤演示<br>• 申请权限流程（哪个群、找谁）<br>• 仓库结构：`product/` `infra/` `ai-service/` |
| **互动引导** | 「现在跟着我做：ssh-keygen -t ed25519 → cat ~/.ssh/id_ed25519.pub，把公钥发给我或者去 GitLab 设置里添加」 |
| **讲师提示** | • 走下来演示一遍，边做边讲<br>• 学员常见问题：SSH 权限、网络不通——提前准备好排查方案 |

#### 幻灯片 24：Git 工作流与规范（10 min）

| 项目 | 内容 |
|---|---|
| **讲解要点** | • 分支策略：Git Flow 或 Trunk-based——视所在子团队而定<br>• Commit Message 规范：Conventional Commits（`feat:` `fix:` `chore:` 等）<br>• PR 模板结构：描述 + 改动列表 + 测试方法 + 影响范围<br>• Code Review 流程：创建 PR → 指定 Reviewer → Review 通过 → Merge<br>• **铁律：禁止直接 push 到 main** |
| **互动引导** | 「这可能是你们未来被 Code Review 最多的环节——我们来模拟一个 CR 场景？」 |
| **讲师提示** | • 这部分讲规范，容易枯燥——尽可能用案例和对比<br>• 准备一个「好的 PR 示例」和「不好的 PR 示例」对比展示 |

#### 幻灯片 25：API Key 与模型网关配置（10 min）

| 项目 | 内容 |
|---|---|
| **讲解要点** | • Key 申请流程：内网平台自助申请，需要部门审批<br>• `.env` 文件配置规范——**绝对不要提交到 Git**（用 `.gitignore` 确认）<br>• 网关地址（给出统一的 Base URL）<br>• Rate Limit 说明：每分钟请求数限制、超出后的重试策略<br>• 模型 Endpoint 对照表：每个模型的 URL、模型名、价格 |
| **互动引导** | 「大家先申请 Key，我们等一下所有人批下来再继续」 |

#### 幻灯片 37：RAG 架构拆解（15 min）

| 项目 | 内容 |
|---|---|
| **讲解要点** | • RAG 三步：**Indexing**（文档 → Chunk → Embedding → Vector DB）→ **Retrieval**（问题 → Embedding → 检索相似片段）→ **Generation**（片段 + 问题 → LLM → 回答）<br>• 端到端流程图——这是今天实操的"地图"<br>• 为什么 RAG 比纯 LLM 更好：避免幻觉、知识实时更新、可控性 |

#### 幻灯片 38：文档分块策略（10 min）

| 项目 | 内容 |
|---|---|
| **讲解要点** | • 固定大小分块 vs 语义分块<br>• 分块大小选择：256 tokens（适合 FAQ）/ 512（常规文档）/ 1024（长文档）<br>• 重叠（Overlap）的作用——避免关键上下文被截断<br>• **对比表**：不同策略下的检索质量（recall@k）|
| **互动引导** | 「给定一份 3 页的产品用户手册 PDF，你们觉得用什么分块策略比较合适？」 |
| **讲师提示** | • 分块策略是 RAG 中最容易被忽略但影响很大的环节<br>• 给学员一个速查原则：结构化文档（Markdown）按标题分块；非结构化按 512 tokens + 10% overlap |

#### 幻灯片 39：Embedding 与向量数据库（15 min）

| 项目 | 内容 |

| **讲解要点** | • Embedding 模型：公司提供的 Embedding API + 介绍维度、模型选择<br>• 向量数据库对比：**Chroma**（本地快速实验 → 实操用）、**Milvus**（生产部署）、**pgvector**（基于 PostgreSQL）<br>• 相似度度量：余弦相似度（最常用）、点积、L2<br>• 索引类型：FLAT（精确）/ IVF（近似、更快）|

#### 幻灯片 40：混合检索策略（10 min）

| 项目 | 内容 |
|---|---|
| **讲解要点** | • 纯语义检索的局限：对精确术语、产品代号、缩写不敏感<br>• BM25 关键词检索的补充作用<br>• Hybrid Search 实现方式：加权融合（Weighted Sum）或 RRF（Reciprocal Rank Fusion）<br>• **演示**：查询「2025 Q3 销售额」用不同检索方式的结果差异 |

#### 幻灯片 45：幻觉问题（15 min）

| 项目 | 内容 |
|---|---|
| **讲解要点** | • 幻觉是什么：事实性错误、捏造引用、张冠李戴<br>• 内部原因：训练数据偏差 → 泛化偏差<br>• 外部原因：RAG 检索到无关文档 → 模型"尽力回答"<br>• **缓解策略**：<br>  - RAG 约束：只基于检索材料回答<br>  - Prompt 加限定：「如果你没有足够的信息来回答，就说不知道」<br>  - Grounding 检查：引用原文 → 自动校验引用是否存在<br>  - 输出校验：用另一个模型评估输出质量 |
| **互动引导** | 「你们在实际项目中有没有遇到过 LLM 产生幻觉的情况？怎么处理的？」 |
| **讲师提示** | • 幻觉是生产中最大的风险点之一，这部分值得花时间讲深<br>• 引用公司产品的实际案例更生动 |

| 项目 | 内容 |

| **讲解要点** | • 延迟三来源：模型推理（最重）、网络传输、检索<br>• 优化策略：Streaming 优先 → 语义缓存 → 模型蒸馏 → 预热<br>• **数据表**：各策略的延迟改善对比 |
| **互动引导** | 「你们觉得在实际产品中，用户能接受的最长 AI 回复等待时间是多久？」 |
| **讲师提示** | • Streaming 是最快见效且最简单的方式——强调这一点<br>• 缓存需要注意语义匹配的精度 |

| 项目 | 内容 |

| **讲解要点** | • Token 用量监控：设置每日/每周预算告警<br>• 省钱四招：max_tokens 合理设置、Prompt 压缩（去冗余）、缓存复用、模型分级路由<br>• 实例：某场景 GPT-4 每天 $200 → 混合路由降到 $50 |

#### 幻灯片 48：数据安全与合规（15 min）

| 项目 | 内容 |
|---|---|
| **讲解要点** | • **红线**：客户数据不得外传至第三方大模型——这是法律责任<br>• 数据脱敏（PII）：手机号、身份证、银行卡号识别与过滤<br>• 内容安全审核：输入（用户提问）和输出（模型回答）双向过滤<br>• Prompt 注入防护：<br>  - 不可信用户输入不得直接拼入 System Prompt<br>  - 输入分隔（用特殊标记区分指令和用户内容）<br>  - 输出校验：检查是否输出了系统指令<br>• 审计日志：所有 LLM 调用记录（谁？何时？什么模型？问了什么？）|
| **互动引导** | 「你们在用 LLM API 时，有没有考虑过用户的隐私数据会不会被发送出去？」 |
| **讲师提示** | • 合规是"一票否决"——产品再好看，数据泄露就完了<br>• 强调公司红线，并告诉学员「如果发现有人把客户数据传到境外大模型，请立刻报告」<br>• 这节课可以讲得严肃一点——让学员记住红线 |

|---|---|
| **讲解要点** | 三个案例，每组选 2 人负责 1 个案例的讨论+展示<br>• 每个案例 10 min 小组讨论 + 10 min 展示+讲师点评<br>• 案例一：客服幻觉（安全/质量交叉点）<br>• 案例二：Prompt 注入（安全）<br>• 案例三：成本超限（成本监控） |
| **互动引导** | 「每个组选一个案例来分析，我们 10 分钟后各组选派一个人来讲你们的分析结果」 |
| **讲师提示** | • 案例研讨是模块 6 的教学重点，不要压缩时间<br>• 关键看学员能不能从多角度分析（技术 + 流程 + 管理）<br>• 案例一讲师补充：RAG grounding + 权限控制方案<br>• 案例二讲师补充：输入过滤 + 输出校验 + 防护策略<br>• 案例三讲师补充：监控指标设计（Token 用量、成本曲线异常检测）|

#### 幻灯片 52：模块 6 总结（5 min）
