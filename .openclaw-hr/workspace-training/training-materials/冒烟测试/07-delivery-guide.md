# 冒烟测试培训交付指南

本指南旨在为首次或独立负责交付“冒烟测试”培训的讲师提供一套完整的“组装”与“实施”手册。它说明了如何使用已准备好的全套物料，成功组织并执行一次高质量的培训。

## 二、 培训前、中、后实施流程

### 培训前（建议提前3-5天）
1.  **深度研读**：
    *   通读本指南（07）和讲师手册（04），理解整体流程与核心要求。
    *   阅读需求分析（01）和课程设计（02），明确教学目标与逻辑。
    *   对照PPT大纲（03）和讲师手册（04），梳理您的个人讲解思路。
2.  **物料与环境准备**：
    *   **PPT制作/获取**：依据`03-ppt-outline.md`制作或获取正式培训PPT。
    *   **学员手册分发**：将`05-participant-handbook.md`提前发送给学员，或准备现场纸质版。
    *   **测试题与问卷**：将`06-assessment.md`准备为可发放的版本（如在线问卷）。准备课程反馈问卷链接/二维码。
    *   **环境与账号**：**至关重要**。根据讲师手册（04）的“课前准备清单”，逐一检查并确认：
        *   内部平台、缺陷管理系统、测试环境、沙箱环境可访问。
        *   演示用的标准测试账号、讲师账号有效。
        *   演练用的简化测试案例、测试数据包就绪，并确认分发方式。
3.  **沟通与协调**：
    *   确认培训时间、地点、参与人数。
    *   若有助教，需提前沟通其角色（如：环境支持、小组巡回观察、时间提醒）。
    *   联系运维或平台支持人员，作为技术后援（可告知其培训时间）。

### 培训中（当天）
1.  **开场与定调（模块一前）**：
    *   严格按照讲师手册（04）第1-2页建议进行，快速建立联系，明确课程目标与规则。
    *   强调“实操”导向，鼓励提问与互动。
2.  **模块化教学**：
    *   **遵循但不拘泥**：以讲师手册（04）为指南，结合自身经验组织语言。重点关注【讲解要点】与【讲师提示】。
    *   **时间管理**：参考课程设计（02）的时间表，灵活调整。实战演练（模块三）是核心，需保证充足时间。
    *   **互动引导**：积极使用手册中提供的【互动引导】建议，特别是模块一的案例讨论、模块二的演示提问、模块三的复盘讨论。
    *   **核心演示**：模块二中“环境准备”和“缺陷报告填写”必须进行**现场操作演示**，这是技能传递的关键。
3.  **实战演练管理（模块三）**：
    *   **清晰发布任务**：确保每个小组明确知道做什么、用什么环境、用多长时间。
    *   **主动巡场**：讲师与助教应巡回观察，**记录共性问题**，但不要直接代劳。通过提问引导学员自己解决。
    *   **有效复盘**：引导讨论聚焦于“遇到的问题”和“学到的技巧”，而非单纯汇报结果。
4.  **总结与支持（模块四及结尾）**：
    *   清晰介绍资源路径与协同升级路径，这是学员课后独立工作的保障。
    *   结尾重申行动呼吁，鼓励学员在真实工作中应用。

### 培训后（立即及一周内）
1.  **即时反馈收集**：
    *   培训结束前，发放并引导学员填写**课程反馈问卷**。
2.  **效果评估**：
    *   可在培训结束时或次日，将课后测试题（06）作为随堂测验或自学检查工具发放。
3.  **支持延续**：
    *   将学员手册（05）、关键资源路径汇总（可从手册中摘录）等，通过邮件或群公告再次发送给学员。
    *   主动在协同群中出现一段时间，解答学员初期的疑问。
4.  **复盘与迭代**：
    *   分析课程反馈问卷与测试结果，识别课程亮点与待改进点。
    *   根据实际授课体验与学员反馈，建议对讲师手册（04）或学员手册（05）提出具体的优化建议。

## 三、 新讲师上手路径
如果您是第一次讲授此课程，建议遵循以下路径：
1.  **第一步：通读与理解（1-2小时）**
    *   依次阅读：`01-needs-analysis.md` -> `02-course-design.md` -> `07-delivery-guide.md`（本文件）。理解课程全貌。
2.  **第二步：精读指南（2-3小时）**
    *   精读`04-instructor-manual.md`，对照`03-ppt-outline.md`，逐页理解教学逻辑与要点。
    *   动手操作：尝试访问讲师手册中提到的所有系统、平台、文档，确保自己能熟练操作。
3.  **第三步：模拟演练（1-2小时）**
    *   选取“模块二”中的任一讲解段落（如“第四步：规范提交缺陷报告”），参照讲师手册，进行15分钟的模拟讲解。
    *   录音或录像，回看评估自己的流畅度、时间把控和互动设计。
4.  **第四步：实战观摩与支持**
    *   如果可能，观摩一次资深讲师的授课。
    *   首次授课前，务必与已讲授过的讲师或培训负责人沟通，获取经验与支持。

## 四、 培训当天 Checklist
**开课前2小时**
- [ ] 打印/准备好学员签到表。
- [ ] 检查教室设备：投影、音响、网络。
- [ ] 打开所有需要演示的系统、平台、沙箱环境，确认可正常登录。
- [ ] 准备好标准测试账号列表，并确认可用。
- [ ] 将学员手册、演练任务说明等电子文件就绪。

**开课前15分钟**
- [ ] 学员签到，发放学员手册（若为纸质）。
- [ ] 自我介绍，与早到学员进行简单交流，缓解紧张。
- [ ] 在PPT上显示课程二维码（如有），引导学员加入课程群或获取资料。

**课程进行中**
- [ ] 佩戴麦克风，调整音量。
- [ ] 关注时间，适当调整节奏。
- [ ] 巡场时关注学员操作进度与困惑表情。
- [ ] 记录演练环节的共性问题。

**课程结束后**
- [ ] 展示课程反馈问卷二维码，引导学员填写。
- [ ] 重申支持渠道（导师、文档、协同群）。
- [ ] 关闭教学设备。
- [ ] 与助教简单复盘当日情况。

## 五、 常见问题处理预案

| 问题场景 | 应对策略 | 备注 |
| :--- | :--- | :--- |
| **学员人数超员** | 1. **紧急**：联系行政或培训组织者，协调增加座位或更换场地。<br>2. **调整**：将实操环节改为更多演示与小组讨论结合，确保核心技能传递。<br>3. **物料**：准备额外的学员手册电子版，确保每人可获取。 | 优先确保教学环境安全与基本体验。 |
| **培训进度落后** | 1. **优先级**：首先保障“模块二：技能篇”的核心演示（环境准备、缺陷报告）和“模块三：实战篇”的演练与复盘时间。<br>2. **压缩**：简化“模块一”的讨论环节，或减少“模块四”的讲解时间，将资源路径以清单形式快速发布。<br>3. **延伸**：将Q&A环节移至课后线上进行。 | 核心目标是学员“能做”而非“全听”。 |
| **演示/沙箱环境故障** | 1. **预案启动**：立即启用备用环境或账号（建议提前准备）。<br>2. **临时转换**：如果完全无法访问，切换到讲师手册中的“常见错误”反例进行讲解，或详细描述操作流程与预期结果。<br>3. **事后弥补**：承诺将环境配置指南、演练任务文档在课后发送，供学员自行练习。 | **预防最关键**，务必提前测试。 |
| **学员参与度低/不互动** | 1. **破冰**：采用“配对讨论”或“小组一分钟分享”等小范围互动方式，降低开口压力。<br>2. **激励**：明确告知互动是培训的一部分，并给予积极参与者口头肯定。<br>3. **提问技巧**：将问题具体化、场景化（如“如果你看到这个错误，第一步会点哪里？”），并留出足够的思考时间。 | 讲师需主动营造安全、鼓励的氛围。 |
| **技术问题集中爆发（如多人无法连接环境）** | 1. **统一指挥**：暂停个人练习，进行集体排查，讲师或助教统一演示解决方案步骤。<br>2. **隔离问题**：协助遇到问题的学员逐一检查网络、VPN、客户端等设置。<br>3. **保底方案**：如果多数人受阻，可转为教师主导的演示模式，确保课程核心内容仍被覆盖。 | 助教在此环节作用关键，应提前明确分工。 |
| **时间严重不足** | 1. **果断取舍**：保护核心模块（技能与实战）。可直接跳过Q&A，告知学员课后邮件收集问题。<br>2. **精华传递**：在最后几分钟，用最精炼的语言回顾培训目标与行动号召。 | 预防优于补救，开课时即应强调时间安排。 |
