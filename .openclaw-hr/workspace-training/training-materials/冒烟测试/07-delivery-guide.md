# 冒烟测试培训 - 交付指南

本指南旨在为培训讲师（特别是未参与前期设计的讲师）提供清晰的“培训包”组装与实施路径。通过遵循本指南，您可以高效地利用提供的全套物料，成功交付一次目标明确、流程顺畅的“冒烟测试”培训。

---

## 一、 物料清单（共8份）

确保在培训前获得并熟悉以下全部物料：

1.  **01-needs-analysis.md**：培训需求分析。了解培训的“为什么”，明确受众、痛点与目标，是把握培训深度和重点的基础。
2.  **02-course-design.md**：课程设计。了解课程的整体结构、模块划分、时间分配与教学方法，是把控培训节奏的蓝图。
3.  **03-ppt-outline.md**：PPT大纲。是制作或审核培训演示文稿的直接依据，明确了每页内容与讲解要点。
4.  **04-instructor-manual.md**：讲师手册。**核心执行文件**。提供了逐页的讲解要点、互动引导和讲师提示，是您组织语言、控制流程的关键指引（非逐字稿）。
5.  **05-participant-handout.md**：学员手册。培训中分发给学员的参考资料，便于学员跟课学习与课后回顾。
6.  **06-assessment.md**：课后测试题。用于培训后检验学员学习效果，通常在培训结束后一周内通过线上方式发放。
7.  **07-delivery-guide.md**：本交付指南。培训的“组装说明书”和“现场执行手册”。
8.  **PPT演示文件**：根据 `03-ppt-outline.md` 制作或确认的最终版PPT文件。

## 二、 培训前、中、后实施流程

### **阶段一：培训前（提前1-2周）**

1.  **物料接收与熟悉**：
    - 通读所有物料，重点精读《讲师手册》与《课程设计》，建立对培训全貌的理解。
    - 根据《PPT大纲》检查或制作PPT，确保内容准确、格式清晰。
2.  **内部备课**：
    - 结合自身经验，将《讲师手册》中的要点转化为自己的授课语言。准备1-2个额外的真实案例或问题。
    - 预演关键模块，特别是工作坊和演练部分，预估时间。
3.  **协调与准备**：
    - 确认培训时间、地点（线上/线下）及参训学员名单。
    - 准备培训物料：电子版PPT、《学员手册》（可提前发放电子版或现场打印）。
    - 准备培训环境：确保投影、音响、网络稳定；如需分组，提前规划座位。
4.  **问卷准备**：
    - 准备培训效果评估问卷（可参考培训成功标准自行设计，或使用公司通用模板），并生成二维码或链接。

### **阶段二：培训中（培训当天）**

1.  **开场（课前10分钟）**：
    - 到达会场，调试设备，打开PPT。
    - 欢迎早到的学员，发放《学员手册》，营造轻松氛围。
2.  **授课执行（90分钟）**：
    - 严格按照《课程设计》的时间表与《讲师手册》的指引进行授课。
    - **关键**：注重互动与时间管理。使用《讲师手册》中的“互动引导”活跃气氛，使用“讲师提示”规避常见问题。
    - 核心模块（如工作坊、演练）确保学员有足够时间思考和实践。
3.  **课程结束**：
    - 强调核心价值与行动倡议，清晰引导学员填写培训评估问卷。
    - 感谢学员参与，解答最后几个问题。

### **阶段三：培训后（培训后1周内）**

1.  **反馈收集**：
    - 关闭问卷通道，统计并分析培训评估结果。
2.  **效果跟进**：
    - 在约定时间（如培训后1周），发放《课后测试题》链接，检验学习效果。
    - 可与测试结果不佳或表现积极的学员进行简短沟通，了解原因或收集建议。
3.  **数据复盘与报告**：
    - 结合评估问卷结果和课后测试通过率，形成简单的培训效果报告，记录本次培训的成功之处与待改进点。
4.  **持续优化**：
    - 将本次授课中发现的物料问题或更好的案例，反馈给培训设计团队，用于优化下一版本的培训包。

## 三、 新讲师上手路径

若您是首次讲授本课程，建议遵循以下路径准备：

1.  **第一阶段：自学者（培训前2周）**
    - **任务**：精读《需求分析》、《课程设计》和《讲师手册》，观看或旁听一次过往培训的录像（如有）。
    - **产出**：在《讲师手册》的空白处，写下您对每个讲解要点的理解和准备补充的个人案例。
2.  **第二阶段：试讲者（培训前1周）**
    - **任务**：邀请一位同事作为听众，完整试讲一遍（至少40分钟核心模块）。重点练习互动引导和时间控制。
    - **产出**：获得听众反馈，并根据反馈调整您的讲解节奏和案例。
3.  **第三阶段：正式讲师（培训当天）**
    - **任务**：自信、流畅地执行培训。牢记您的目标是引导学员达成学习目标，而非完美背诵讲稿。
    - **支持**：将本《交付指南》和《讲师手册》放在手边，作为随时的提示。

## 四、 培训当天 Checklist

### **课前检查（培训开始前1小时）**
- [ ] PPT文件已打开，投影显示正常。
- [ ] 翻页笔、麦克风等设备工作正常。
- [ ] 《学员手册》已准备就绪（纸质或电子版链接）。
- [ ] 培训评估问卷二维码/链接已准备好。
- [ ] 讲师本人仪表整洁，状态积极。

### **课中关键节点提醒**
- [ ] **开场**：清晰介绍课程目标和议程（对应PPT第1页）。
- [ ] **模块一**：确保“冒烟测试定义”和“与回归测试区别”讲清（对应PPT第4页）。
- [ ] **模块二**：严格控制小组工作坊时间（讨论7分钟，分享3分钟）（对应PPT第8页）。
- [ ] **模块三**：巡视学员用例编写，收集共性问题（对应PPT第12页）。
- [ ] **模块四**：强调“标准事先共识”的重要性（对应PPT第16页）。
- [ ] **结束**：明确引导填写评估问卷，并感谢学员。

### **课后动作**
- [ ] 确保所有学员已收到问卷填写信息。
- [ ] 整理个人授课笔记，记录现场的亮点和待改进点。
- [ ] 完成《交付指南》中“培训后”的数据复盘动作。

## 五、 常见问题处理预案

以下预案基于真实培训现场可能遇到的问题，旨在帮助您从容应对。

| 问题场景 | 可能原因 | 应对策略 |
| :--- | :--- | :--- |
| **人数超员** | 报名人数超出预期，场地/物料不足。 | 1. **提前沟通**：若预知，提前协调更大场地或分批次培训。<br>2. **现场调整**：增加小组人数；确保电子版《学员手册》可及时分享；优先保障核心参与者（如测试工程师）的体验。 |
| **进度落后** | 学员提问过多、讨论超时、演练环节耗时过长。 | 1. **灵活压缩**：非核心内容的讲解可适当精简，但**目标相关的模块（如演练、分析）不可省略**。<br>2. **关键提醒**：在每模块开始时重申时间目标，讨论环节前明确截止时间。<br>3. **课后补充**：将未深入讨论的优质问题收集起来，承诺课后通过邮件或群聊分享见解。 |
| **设备故障** | 投影无信号、网络中断、音频失效。 | 1. **备用方案**：准备PPT的PDF版本于U盘；熟悉内容，可脱稿进行关键部分讲解。<br>2. **化整为零**：若投影不可用，可引导学员围坐，通过讨论和分享《学员手册》内容继续。<br>3. **寻求支持**：立即联系现场IT或行政支持人员。 |
| **学员不参与** | 学员沉默、低头看手机、对活动反应冷淡。 | 1. **主动互动**：采用点名邀请、小组快速分享等方式，增加参与感。<br>2. **关联实际**：多问“在大家的项目中，类似情况是如何处理的？”将内容与工作紧密挂钩。<br>3. **降低压力**：对于演练或提问，先给予安全提示（“我们只是探讨，没有标准答案”），鼓励分享。 |
| **技术问题引发争议** | 对“阻塞性缺陷”的定义、用例优先级等产生不同理解。 | 1. **回归共识**：将讨论拉回到《讲师手册》中定义的标准和《需求分析》中明确的痛点上。<br>2. **记录差异**：如果无法立即达成一致，记录下不同观点，并说明这正是需要团队后续沟通以建立共识的点。<br>3. **避免陷入**：不作为技术裁判，而是引导大家思考如何在流程中建立决策机制。 |
