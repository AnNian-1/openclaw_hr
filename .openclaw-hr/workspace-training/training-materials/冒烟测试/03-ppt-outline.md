# 冒烟测试培训 PPT 大纲

**课程总时长**：90分钟
**PPT 结构说明**：本大纲遵循课程设计（02-course-design.md）的模块结构，通过过渡页实现模块间的自然转换。每页PPT的要点均为具体内容，讲师可直接用于讲解。

| 页码 | 标题 | 类型 | 要点 | 所属模块 | 建议时长 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 0 | 封面 | 封面页 | - 课程名称：冒烟测试实战指南<br>- 讲师姓名/部门<br>- 某某公司 · 测试与质量部 | 开场 | - |
| 1 | 课程议程与目标 | 导入页 | - 四个核心模块概览：概念澄清、场景识别、用例编写、评估改进<br>- 本次培训的总体目标：建立统一认知与执行标准<br>- 学习产出：能识别、编写并评估一次冒烟测试 | 开场 | 5分钟 |
| **2** | **模块一：导入与概念澄清** | **模块过渡页** | - 本模块目标：理解冒烟测试“是什么”和“为什么重要”<br>- 预计时长：15分钟<br>- 核心问题：我们为什么需要一道“快速准入验证”？ | 模块一 | 0.5分钟 |
| 3 | 当前发布前的挑战 | 内容页 | - 痛点回顾：新版本缺乏统一准入验证<br>- 后果：缺陷后移，影响研发效能与产品口碑<br>- 核心诉求：我们需要一个标准化的“守门员”流程 | 模块一 | 4分钟 |
| 4 | 冒烟测试：定义与价值 | 内容页 | - 定义：在版本详细测试前，对核心功能进行的快速、高优先级的验证<br>- 核心价值：尽早发现重大阻塞问题，保障后续测试顺利进行，节约总体成本<br>- 与回归测试的核心区别：范围（最核心 vs 全面）、时机、目的 | 模块一 | 5分钟 |
| 5 | 冒烟测试在研发流程中的位置 | 内容页 | - 流程图示：需求 -> 开发 -> **冒烟测试** -> 系统/回归测试 -> 发布<br>- 关键角色：测试（执行与判定）、开发（配合自测与修复）、产品（明确核心路径）<br>- 时机：版本转测试后，正式测试开始前 | 模块一 | 5分钟 |
| **6** | **模块二：关键场景识别（协同云 & 数据洞察）** | **模块过渡页** | - 本模块目标：掌握如何识别核心冒烟场景（目标T2）<br>- 预计时长：20分钟<br>- 核心方法论：从用户旅程中提炼必验路径 | 模块二 | 0.5分钟 |
| 7 | 场景识别方法论 | 内容页 | - 核心原则：覆盖产品最核心的“快乐路径”和关键业务流<br>- 方法：基于用户旅程地图，梳理“登录-核心操作-达成目标”的关键步骤<br>- 思考问题：如果此功能失败，是否会导致产品核心价值完全无法使用？ | 模块二 | 5分钟 |
| 8 | 案例工作坊：识别「协同云」核心场景 | 内容页 | - 案例背景：以「协同云」近期一个真实需求（如“项目任务快速创建”）为例<br>- 小组讨论指引：1. 该需求的核心用户目标是什么？ 2. 达成目标的必经步骤有哪些？ 3. 哪些步骤失败会导致整个功能不可用？<br>- 产出：小组代表陈述识别出的核心冒烟场景（如：用户能成功创建带指定字段的任务） | 模块二 | 10分钟 |
| 9 | 从案例到通用清单框架 | 内容页 | - 讲师点评：总结各组的识别逻辑与共性<br>- 提炼框架：对于「协同云」和「数据洞察」，冒烟场景应重点关注：用户登录与鉴权、核心业务流程创建/提交、关键数据展示/计算、与外部系统的核心集成点<br>- 强调：清单是动态的，需随版本迭代更新 | 模块二 | 4分钟 |
| **10** | **模块三：用例编写与执行实践** | **模块过渡页** | - 本模块目标：掌握规范编写与初步分析能力（目标T3， T4）<br>- 预计时长：30分钟<br>- 核心任务：将识别的场景转化为可执行、可判定的用例 | 模块三 | 0.5分钟 |
| 11 | 冒烟测试用例编写规范 | 内容页 | - 必备要素：用例ID、标题、前置条件、测试步骤（清晰）、预期结果（明确）<br>- 编写要点：步骤应具体到可操作；预期结果必须可验证、无歧义<br>- 模板示例：展示一个符合规范的用例（以「数据洞察」报表导出功能为例） | 模块三 | 5分钟 |
| 12 | 实操演练：编写核心冒烟用例 | 内容页 | - 演练任务：基于模块二识别的场景（如「协同云」任务创建），每位学员编写1条冒烟用例<br>- 要求：使用规范的模板，关注前置条件（如用户已登录、项目已存在）和关键验证点<br>- 讲师巡视指导，收集共性问题 | 模块三 | 10分钟 |
| 13 | 执行要点与常见问题 | 内容页 | - 环境与数据：确保测试环境稳定，数据满足前置条件（可提前准备数据脚本）<br>- 执行纪律：严格按用例步骤执行，真实记录结果，不可跳过或假设通过<br>- 常见问题：环境部署失败、基础数据缺失、用例步骤不清晰导致误判 | 模块三 | 5分钟 |
| 14 | 失败分析演练 | 内容页 | - 案例：展示一个典型的冒烟测试失败报告（如：“协同云-项目列表加载超时”）<br>- 分析引导：1. 失败现象是什么？ 2. 可能的原因链？（网络问题？前端代码？后端接口？数据库？） 3. 如何初步定位？<br>- 小组讨论，区分是环境问题、代码缺陷还是需求理解偏差 | 模块三 | 9分钟 |
| **15** | **模块四：评估标准与持续改进** | **模块过渡页** | - 本模块目标：学会评估结果并推动流程优化（目标T5）<br>- 预计时长：15分钟<br>- 核心议题：如何判定“通过”并驱动质量提升？ | 模块四 | 0.5分钟 |
| 16 | 冒烟测试的通过/失败标准 | 内容页 | - 通过标准：所有冒烟用例执行通过，无阻塞性缺陷（需明确定义“阻塞性”）<br>- 失败标准：出现任何导致核心功能无法使用的缺陷<br>- 决策流程：测试负责人汇总报告，与开发、产品快速确认，明确是否阻塞后续测试<br>- 共识：标准必须在团队内事先达成一致，避免临场争议 | 模块四 | 5分钟 |
| 17 | 报告解读与度量 | 内容页 | - 冒烟测试报告核心信息：执行用例数、通过率、失败用例详情、环境问题记录<br>- 关键度量指标：冒烟通过率、平均执行耗时、冒烟阶段发现的缺陷数<br>- 如何用数据驱动改进：分析失败主要原因，针对性优化（如环境稳定性、用例覆盖度） | 模块四 | 4分钟 |
| 18 | 持续优化循环 | 内容页 | - 优化循环：Plan（规划/更新用例）-> Do（执行）-> Check（度量分析）-> Act（改进流程、用例、环境）<br>- 讲师角色：测试负责人应定期回顾冒烟测试有效性，组织用例评审<br>- 行动倡议：将本次学习成果应用于下个版本的冒烟测试实践中 | 模块四 | 3分钟 |
| 19 | 课程总结与关键要点回顾 | 总结页 | - 重申冒烟测试的价值：质量第一道关口，提升发布信心<br>- 四个模块核心收获回顾：概念统一、场景聚焦、用例规范、评估有据<br>- 下一步行动：在即将到来的版本发布中，实践所学流程 | 总结 | 2分钟 |
| 20 | Q&A | 互动页 | - 讲师引导提问与解答<br>- 鼓励分享个人实践中的具体困惑 | Q&A | 5分钟 |
| 21 | 培训效果评估 | 结束页 | - 请学员扫描二维码或链接，填写培训效果评估问卷<br>- 感谢参与！ | 结束 | 3分钟 |
