# HR 数字员工开发实战 · 培训子 Agent 搭建与实践手册（Lesson 2-2 实操）

> 本文是 `OpenClaw AI HR 数字员工开发实战 · Lesson 2-2 入职 + 培训子 Agent`（共 70 页）中**培训子 Agent** 部分的动手落地手册。**理论篇见 `7.AIHR培训子Agent搭建理论方法论.md`**——本文只讲"怎么做"，"为什么"请回理论篇。
>
> **范围说明**：本手册只覆盖培训子 Agent（原文 §5，ADDIE 生成 Pipeline）。入职子 Agent（§2-§4，Lobster 工作流）见 `5.`/`6.` 两篇。
>
> **本手册目标**：把培训物料生成能力，从"靠人手敲多次调用"，按 OpenClaw 工业四步重构成 **一个** 可装、可测、可复用、可换主题的 markdown 指令型 Skill（`generating-training-materials`）并端到端跑通。
>
> **交付边界**：只产 8 份文本物料。历史实验中的 `generating-training-figures` **已裁撤**（详见理论篇 §7），本手册不再教配图封装。

## §0 培训子 Agent 全景与交付目录

培训物料生成能力封成 **一个 Skill**（不是 `addie-pipeline.py`，也不再是一摞手敲 prompt）：

| Skill | 形态 | 封装对象 |
|---|---|---|
| `generating-training-materials` | markdown 指令型 + 交付前自检脚本 | ADDIE 五阶段 prompt 链（步骤 0→7）+ 步骤 8 对照 `evals/eval-cases.md` / `scripts/self_check.py` |

完整 workspace 目录（现行）：

```
workspace-training/
├── SOUL.md / AGENTS.md / TOOLS.md              persona 文档
├── skills/
│   └── generating-training-materials/          唯一交付 Skill
│       ├── SKILL.md                            步骤 0→8（含交付前自检）
│       ├── references/stage-prompts.md
│       ├── scripts/self_check.py               结构自检（可机器化部分）
│       └── evals/eval-cases.md                 评测 / Agent 自我校验说明书
├── source-docs/                                3 份星桥科技真实 HR 文档（需求分析素材）
└── training-materials/                         ADDIE 产出的全套 8 份 Markdown 物料
```

> **配图**：`generating-training-figures` 已裁撤，不在交付目录内。若磁盘上仍有该目录或 `figures/`，视为历史残留，Agent 不要主动触发（理论篇 §7）。

## §1 工业四步操作模板（通用）

本课交付的 Skill 走这四步：

```bash
# ① 建 Skill：标准一层布局
#   skills/<name>/
#   ├── SKILL.md        （必需：frontmatter + 渐进式披露正文，≤500 行）
#   ├── scripts/        （可选；本 Skill 有 self_check.py 做交付前结构自检）
#   ├── references/     （详细文档 / prompt 模板，按需一层引用）
#   └── evals/          （评测场景 = 作者验收 + Agent 自我校验说明书）

# ② 改核心 md 文档
#   TOOLS.md  —— 加"做什么 / 什么时候用 / 形态 / 调用要点"
#   AGENTS.md —— 加调用时机与工作流编排（精确字符串插入，不整文件覆盖）
#   SOUL.md   —— 更新占位状态 + 补硬边界

# ③ 改配置（主动确认，即使无需改也不能省）
$OPENCLAW_HR_BIN config get 'agents.list[3].tools'    # training 工具权限
$OPENCLAW_HR_BIN skills check --agent training         # skill 启用表

# ④ 调用测试
$OPENCLAW_HR_BIN skills info <name> --agent training   # A. 验证加载 ✓ Ready
#   B. 发不点名 Skill 的自然任务，验证 Agent 自己触发
#   C. 验证真跑（阶段承接对不对、8 份物料齐全），不是 Agent 假装跑
#   D. 验证步骤 8：对照 evals/eval-cases.md，并跑 scripts/self_check.py
```

> 工业四步完整方法论见 Lesson 2-1（`4.AIHR招聘子Agent搭建与实践手册.md` §1）。

## §2 裸做法：先不用 Skill 跑一遍 ADDIE

**工业方法论第一步不是写代码，是先用最朴素的方式把功能跑一遍**，看清两件事：功能要做到什么程度、裸做法每次要补哪些上下文。

ADDIE 五阶段产 8 物料的裸做法，就是一条 prompt 链——5 个阶段、多次调用（全部生成文本物料）：

```bash
$OPENCLAW_HR_BIN agent --local --agent training -m "..."   # 每次 prompt 写死"读哪几个前阶段文件、产出哪个文件、有哪些核心要求"
```

每次调用产出落盘 `training-materials/`，下一次调用再读进来。一次完整跑通的真实产出：**8 个 Markdown 文件、3010 行、约 6.9 万字**（现行不含配图）。

**裸做法的真实痛点**（就是 `generating-training-materials` 要装进去的东西）：
- **整条工作流每次靠 Agent 临场重建。** 不点名 Skill 让 Agent 说怎么做，它确实能说出 ADDIE 五阶段、8 份物料（ADDIE 是它训练数据里的通用知识），但 8 份物料的文件命名、每份输入来源、每份 prompt 核心要求全是临场发挥的——这次对得上，换个会话、换个措辞就可能漂移（少一份物料、文件名不一致、讲师手册又偷偷写回逐字稿）。
- **关键的硬约束没被当成硬约束。** 比如"讲师/学员手册都基于 03 PPT 大纲这个单一内容源、不各自重读 source-docs"——这条是物料一致性的关键，但裸做法里它只是 Agent 这一次的选择，不是写死的规则。
- **产出的是一次性、不可复用的计划。** 下次做另一个主题又要重发一长串 prompt。

## §3 generating-training-materials（markdown 指令型 Skill）

**把手敲的 ADDIE prompt 链，封成一个 Agent 自己会用的 markdown 指令型 Skill。**

### 3.1 第一步 · 建 Skill

标准布局（主体仍是 markdown 指令型；**另附交付前结构自检脚本**——阶段生成无确定性脚本可封，但「8 份是否齐全 / T1-T5 / 对应矩阵」可机器核）：

```
generating-training-materials/
├── SKILL.md                    frontmatter + 步骤 0→8（含交付前自检）
├── references/stage-prompts.md ADDIE 7 次生成调用的 prompt 模板
├── scripts/self_check.py       结构自检（对照 eval-cases 可机器化部分）
└── evals/eval-cases.md         4 个评测场景（作者评测 + Agent 自我校验说明书）
```

> **`evals/eval-cases.md` 不是装饰**：流水线跑完后 Agent **必须**读它做步骤 8；只生产不验收等于 Skill 失败。结构项先跑 `self_check.py`，判断项（是否真读了上一阶段文件等）按场景 `expected_behavior` 人工核。

frontmatter：

```yaml
---
name: generating-training-materials
description: Generate a complete, internally consistent set of training
  materials from source documents via the ADDIE five-stage pipeline
  (eight Markdown deliverables), then run a mandatory self-check against
  evals/eval-cases.md and scripts/self_check.py before claiming delivery...
metadata:
  openclaw:
    requires:
      bins: ["python3"]
---
```

> 要点：`name` 用动名词、小写加连字符；`description` 含 what（ADDIE 产 8 份物料）+ when（办内训）+ **交付前自检**。生成步骤靠 `group:fs`；自检声明 `requires.bins: [python3]`。

### 3.2 正文关键设计（markdown 指令型 + 交付前验收）

正文用 workflow / checklist 模式，把 ADDIE 拆成步骤 0→7（生成）+ **步骤 8（自我校验）**，每步写清"读什么 → 用哪个模板 → 产出什么 → 完成判据"；prompt 模板一层引到 `references/stage-prompts.md`。

1. **把"流水线"翻译成"有序步骤清单"。** 步骤 0 准备、1–7 各对应一次生成调用、**8 对照 eval-cases 自检**。Agent 不需要理解 ADDIE 方法论，只需要"从步骤 0 往下走、不跳过 8"。
2. **每一步写死三件事：读什么、产出什么、完成判据。** 判据要具体、可自检（"两份文件落盘""末尾有对应矩阵"）。
3. **prompt 模板与工作流编排分离——渐进式披露。** 7 段模板在 `references/`；验收说明书在 `evals/`；结构裁判在 `scripts/self_check.py`。
4. **阶段承接 / 换主题复用 / 评测驱动**写进硬规则：后一步先读前一步文件；换主题只改模板 1；改行为先改 `eval-cases.md` 再改 SKILL。

### 3.3 建完立即验证加载

```bash
$OPENCLAW_HR_BIN skills info generating-training-materials --agent training
```

输出 `✓ Ready`、`Source: openclaw-workspace`、`Visible to model: yes`；现行 frontmatter 声明 `requires.bins: [python3]`（给 `self_check.py`），`skills info` 应能看到对应 Requirements。

### 3.4 第二步 · 改核心 md 文档

摸底确认 training 的 `AGENTS.md` / `TOOLS.md` 还是 OpenClaw 默认模板（讲 group chat 礼仪、heartbeat，没有一句培训业务）、`SOUL.md` 做了培训定制但还标占位状态。materials Skill 一并写入：

- `TOOLS.md` —— 加"培训业务 Skill 清单"：形态写清「步骤 0→8 + self_check + eval-cases」；调用要点含交付前自检命令。
- `AGENTS.md` —— 加"培训业务工作流"：ADDIE 串联 + **交付前必须自我校验**硬规定；具体步骤照 SKILL.md（含步骤 8）。
- `SOUL.md` —— 更新占位状态为"能力已就位"并列本 Skill（含自检）；「我的边界」补合规红线与真实性纪律。

> 改法：先 Read 看清当前内容，再用**精确字符串替换插入**新段落、不整文件覆盖（`AGENTS.md` 默认模板有大量 group chat / heartbeat 内容要原样保留）。

### 3.5 第三步 · 改配置

```bash
$OPENCLAW_HR_BIN config get 'agents.list[3].tools'    # allow 已含 group:fs（读写物料需要），已在
$OPENCLAW_HR_BIN skills check --agent training         # Blocked by allowlist: 0
```

> 本课实操**明令不许 `config set` 改 `openclaw.yaml`**（它是隔离环境共享资源）。所幸本步确认无需改配置。如果你自己的场景发现需要改配置（比如 Agent 还没有 `group:fs`），就要把它当成单独一步认真做，不能跳过。

### 3.6 第四步 · 调用测试

**测试 B · Agent 自己触发 + 跑通 ADDIE 前阶段**（prompt 里显式声明产出文件不存在，堵死幻觉）：

```bash
$OPENCLAW_HR_BIN agent --local --agent training --timeout 480 -m \
  "我们要给星桥科技新员工办一场入职培训，source-docs/ 里有真实 HR 文档。请帮我做培训物料。training-materials/01-needs-analysis.md 和 02-course-design.md 这两个文件目前不存在，不要假设它们已存在。先把 ADDIE 流水线的第一阶段（需求分析+课程设计）真正做出来，产出落盘。"
```

Agent 真做了——落盘 `01-needs-analysis.md`（108 行，含按布鲁姆认知层次写的 5 项培训目标 T1-T5、受众痛点、成功标准）和 `02-course-design.md`（295 行，末节正是"模块与培训目标对应矩阵"）——与 SKILL.md 步骤 1 完成判据逐条对上。

**测试 C · 验证阶段承接**（markdown 指令型的核心价值"阶段承接不断链"，必须专门验证。删掉旧 03，让 Agent 续跑）：

```bash
$OPENCLAW_HR_BIN agent --local --agent training --timeout 540 -m \
  "ADDIE 流水线的需求分析和课程设计阶段已经做完了（01/02 已落盘）。请继续往下走，做下一阶段该产出的物料。03-ppt-outline.md 目前不存在，不要假设它已存在。产出落盘后告诉我你这一步读了哪些文件。"
```

Agent 产出 `03-ppt-outline.md`（353 行、21 页 PPT），并在回复里明确列出读了 `01-needs-analysis.md`（取 T1-T5、痛点、约束）和 `02-course-design.md`（取 5 模块结构、时间表）——照 SKILL.md 步骤 2 写死的"读 01 和 02"做了，没跳过去重读 source-docs。**阶段承接的硬证据**：实测 03 的 5 个课程模块与 02 的 5 个模块逐字对应。

> **验证范围说明**：调用测试真实跑了步骤 1（A+D 阶段）和步骤 2（PPT 大纲），共两次调用，覆盖了 markdown 指令型 Skill 最关键的两点——"Agent 照编号步骤走"和"阶段承接不断链"。步骤 3-7 是同一种模式；**步骤 8 必须单独验**：8 份落盘后跑 `self_check.py`，并对照 `evals/eval-cases.md` 场景 1/2 的判断项。自检未通过却声称交付 = 测试失败。

**测试 D · 交付前自我校验**：

```bash
python3 skills/generating-training-materials/scripts/self_check.py \
  --outdir training-materials/<主题或根目录>
# 退出码 0 = 结构项通过；再按 evals/eval-cases.md 人工核阶段承接等判断项
```

## §4 配图 Skill 已裁撤（历史说明）

早期实验曾封装 `generating-training-figures`（matplotlib 脚本型 Skill），用于在 8 份文本物料之后批量出结构图，并踩过「同名旧脚本旁路」「退出码 0 但图画错」等坑。

**现行决策：该 Skill 不再纳入培训子 Agent 交付。** 原因见理论篇 §7——核心价值在文本 Pipeline；图内容写死在代码里不读源文档；维护与校验成本高。

动手时请：

1. **不要**再按旧手册建 / 测 `generating-training-figures`。
2. persona（`AGENTS.md` / `TOOLS.md`）若仍写「配图后置」，应改为只描述 `generating-training-materials`。
3. 磁盘上若还有该 Skill 目录或 `training-materials/figures/`，可保留作考古，但 Agent **不应主动触发**。

双 Claude 迭代方法仍用于 materials Skill：真跑 → 观察阶段承接 / 文件名漂移 → 写回 SKILL.md（理论篇 §8）。

## §5 完整附件清单与改造路径


**适用版本**：OpenClaw v2026.5.12 stable + DeepSeek V4 Pro（API 模型 ID `deepseek-v4-pro`；OpenClaw 配置里带 provider 路由前缀写作 `deepseek/deepseek-v4-pro`）。

### 一、Skill 与配置类

| 文件 | 作用 | 使用 / 改造路径 |
|---|---|---|
| `skills/generating-training-materials/` | markdown 指令型 Skill——把 ADDIE 五阶段 prompt 链封成标准工作流。SKILL.md 编排步骤 0→7，`references/stage-prompts.md` 放 prompt 模板 | 换主题改【模板 1】对素材和受众的描述；加一种物料类型在 SKILL.md 加步骤、`references/` 加模板 |
| persona 文档 | `SOUL.md` / `AGENTS.md` / `TOOLS.md`——materials Skill 的调用时机与边界 | 改人设改 `SOUL.md`；加新能力照工业四步第二步补写 |
| training 工具权限 | `agents.list[3].tools.allow`。物料生成实际主要用 `fs` | 按最小权限可收敛到 `group:fs`（及确需的 memory/web）；数组单元素改写用 bracket 索引 |

### 二、数据样本类

| 文件 | 数量 | 作用 |
|---|---|---|
| `source-docs/` | 3 份 | 星桥科技真实 HR 文档（公司简介、培训与晋升通道、入职流程），需求分析阶段素材输入 |
| `training-materials/01 ~ 08`（`.md`） | 8 份 | 完整培训物料样本（历史产出；其中讲师手册正文仍可能含旧版逐字稿）。现行 Skill 已改为讲解要点版，新跑勿再产逐字稿 |

> 物料样本是给你看产出形态用的——直接打开就能判断这条 Pipeline 的输出质量（讲师手册讲解要点/控场是否到位、测试题有没有详解）。历史样本里的「逐字稿」仅作考古，不以之为现行标准。

### 三、拿到附件包后的推荐路径

1. **先看物料样本**——打开 `training-materials/` 里的 8 个文件，看一遍 Pipeline 真实产出长什么样，建立"工业级培训物料"的标准。
2. **装上 materials Skill 跑通一轮**——把 `skills/generating-training-materials/` 放进 training 子 Agent 的 `workspace/skills/`，`skills info` 验证被识别，发自然任务（"给某主题做一套培训物料"）让 Agent 触发本 Skill、照 ADDIE 步骤跑完 8 份 Markdown。
3. **换成自己的主题（最常用、复用红利最大的改造）**——换主题只改一处：把 `source-docs/` 换成自己培训主题的素材文档，再改 `generating-training-materials/references/stage-prompts.md` 里【模板 1】对受众和目标的描述。后面 6 个步骤的 prompt 模板不用动（它们吃前阶段产出文件，主题自动顺着 Pipeline 往下传）。
4. **加一种物料类型**——比如加一份"培训宣传海报文案"。在 SKILL.md 加一个步骤、`references/stage-prompts.md` 加一段 prompt 模板、指明它读哪几个前阶段文件即可。

> **生产前必读的两条约束**：① 附件里的物料样本是 AI 辅助生成的教学示例，任何培训物料对外交付前必须经讲师审核；② 每份交付物料都应带"AI 辅助生成、讲师审核后交付"的标注——这是合规红线，不是可选项。（详见理论篇 §10）

## 附录 A：ADDIE 五阶段 prompt 清单要点

SKILL.md 正文把 ADDIE 拆成编号步骤 0→7，每步"读什么 → 用哪个模板 → 产出什么 → 完成判据"：

| 步骤 | 阶段 | 读什么（输入） | 产出（输出） | 完成判据要点 |
|---|---|---|---|---|
| 0 | 准备 | 确认 `source-docs/` 三份 HR 文档就位 | — | 素材齐 |

| 2 | Dev PPT 大纲 | `01` + `02` | `03-ppt-outline.md` | 每页含页码/标题/要点/所属模块/时长，与课程设计模块一一对应 |
| 3 | Dev 讲师手册 | `03`（单一内容源） | `04-instructor-manual.md` | 每页讲解要点（3～6 条）+ 互动 +【讲师提示】；**禁止逐字稿** |
| 4 | Dev 学员手册 | `03`（单一内容源） | `05-participant-handbook.md` | 5 模块划分、各模块知识点、速查 Q&A |
